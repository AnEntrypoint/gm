# Brief: txiki.js engine, run_code and leaves (components/quickjs, native/third_party/txiki)

Supersedes the QuickJS-NG brief. The engine under run_code, the leaves and query_log is an embedded txiki.js runtime: QuickJS-NG with a libuv event loop and txiki's web globals. Read tasks/rewrite/common.md and native/include/gm/leaves.hpp, host.hpp, then DESIGN.md sections "Hot reload language (2026-11-04)" and "Embedded txiki.js runtime (2026-11-10)".

1. Vendoring. `node tools/vendor-txiki.mjs` downloads three pinned archives, checks each sha256, and writes native/third_party/txiki: txiki.js v26.11.0, libuv dd9f081, quickjs-ng 7b5f588 (URLs, hashes and the file lists are in native/third_party/txiki/VERSION.txt). The tool writes non-ASCII comment characters as ASCII and refuses one outside a comment. Nothing under native/third_party/txiki is edited by hand.
2. What is built. gm_quickjs_ng is the four QuickJS-NG sources from the pin. gm_txiki is txiki's runtime core (vm, modules, builtins, timers, fs, streams, os, sys, process, dns, udp, channel, fswatch, worker, url with ada, and the precompiled core, polyfills and stdlib bundles) on libuv's own CMake target uv_a. The txiki modules that need libwebsockets, mbedtls, wamr, libffi, sqlite3, miniz or mimalloc are not vendored; native/components/quickjs/txiki/txiki_stubs.c answers their entry points and overlay/ holds the three small headers private.h includes for them. txiki_shim.c is the only file that reads txiki's private header; engine.cpp sees it through txiki_shim.h.
3. Engine (engine.hpp, engine.cpp). One fresh runtime per call: gm_txiki_new creates a TJSRuntime with its own uv loop, and the engine takes its JSContext. TJS_Initialize and TJS_Run are not called, so gm keeps its own stdout and drives the loop itself. The engine sets the interrupt handler, replaces the module loader with gm's (a leaf's or a body's relative imports resolve from its own directory; a `tjs:` name goes to txiki's builtin loader), and resets the globals: console is silent until run_code installs its sink, and alert, confirm and prompt are removed. txiki defines its host API `tjs` as a frozen, non-configurable global, so it cannot be removed; run_code shadows it with an unset parameter of the body function, so a body's own text reaches the host only through gm verbs. A module the body imports, and a leaf, can still name `tjs`. txiki owns the context opaque, so a Session is found through session_of(ctx).
4. Timers. libuv starts a timer from the loop's cached time, which is as old as the last loop turn because JavaScript runs outside uv_run here; the engine wraps setTimeout and setInterval to refresh that time first (before the wrap a 300 ms timer fired after 296 ms). settle. Pending jobs are drained, and while the promise is pending and the loop is alive the engine turns the loop once without blocking, drains again and checks the deadline. A promise that is pending with no live handle ends as before, not finished.
5. LeafVerbs, run_body and query keep their behaviour: metadata cached per (path, mtime, size), bytecode through JS_WriteObject and JS_ReadObject, the last good bytecode kept on a compile error, generation bumped on a change that compiles.
6. Deadline per call through JS_SetInterruptHandler, 120 s by default, an error on expiry; the same check runs between loop turns, where no JavaScript runs.
7. MSVC. txiki's C sources are not built with MSVC, so GMNEW_TXIKI defaults OFF there and the engine is plain QuickJS-NG from the same pin (the #else branches in engine.cpp). Not verified on Windows here.
8. Witnesses: tools/check-embedded-runtime.mjs (timers, URL, hidden host API, console off the protocol stream, relative import, native and leaf verbs, a never-settling promise, cost per body) and tools/check-build.mjs with the existing checks unchanged.
Spec for run_body: src/runcode.mjs and src/body-worker.mjs.
