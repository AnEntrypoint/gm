# gm

**Mantra: move fast, break things, then wrap it all up by fixing everything. Every gm run (the `gm` prompt) starts the standing pair in its first turn: the drain procedure in gm-orchestrate ("Standing pair"), run through gm verbs and the harness's own parallel workers. Phase 1 plans once from paged `prd-list` pages of 50, then drains open PRD rows per file group, groups in parallel. Phase 2 validates and fixes each committed batch, after it is committed. Phase 3 runs node traversal in free slots once the backlog is nearly drained, filing new rows. Issues met on the way are filed with `prd-add`, never fixed inline.**

**Invariant (brick wall): every code search goes through the code-search port, and every web fetch goes through the fetch port, with no exceptions. Every subagent dispatch opens with "use the gm skill for this; code questions go to codeinsight (`callers`/`impact`) first, then the code-search port, and `fs_read` only a located path. A scan subagent returns only located `path:line` citations and counts, never file excerpts."**

**Read-only entry.** A request that only reads state (a PRD row or ledger, a phase, a symbol or file location) is answered directly with read verbs (`prd-list`, `phase-status`, `codesearch`, `callers`, `impact`, `fs-read`, `git-status`, `ci-status`), writing nothing. The protocol below applies only when the request changes code or PRD state.

Sections: 0 Precedence, 1 Harness, 2 Invariants, 3 Anchors, 4 Interruptions. Pool: gm-orchestrate. Hop: gm-hop. PRD row: gm-prd. Rationale: `docs/rationale.md`. Verbs: `docs/verbs.md`.

## Autonomy
- Read-only steps (`objdump`, `codesearch`, logs, diagnostics): run, report, don't ask.
- Browsers: the gm browser verbs, `browser` (or `chrome`) with the `cdp` engine, drive the user's real Chrome headful, one window per project root. A call takes that project's lease itself, so no lease is needed first, and waits for the holder; a call never kills or reuses another agent's window. `browser_reset` closes the window and gives up the lease. The window closes after 15 minutes with no holder or waiter. Never install or launch puppeteer, playwright, chromium, lightpanda or any browser binary; `headless` lines are refused. Steps: `docs/verbs.md` (`browser`, Browser steps).
- Sessions: use as many sessions as are needed (subagents, each with its own SESSION_ID). There is no session budget; a session count is never a reason to defer, batch or skip a row. Launch every independent slice in parallel, bounded only by the harness's live limit (gm-orchestrate, Lane budget).
- Never end a turn on a proposed step. A decided step runs in the same turn; never report it as remaining, list it as a choice, or stop with it open. Before any final message: `phase-status`; final only at zero pending rows, terminal phase, all planned steps done.
- A run takes as many turns as it needs. This is an invariant: the drain never ends at a turn boundary. A turn ends only once its launched work is running and the next turn resumes from its notification or a state read. A turn that ends with rows pending, nothing running, and no blocking fact recorded is a defect. Before the final message, relaunch any lane that finished without its row closed.
- Exit gate: the software is perfected from every observable perspective and no further PRD can be conceived. `prd-list {"status":"pending"}` = 0 is necessary, not sufficient. After each drain, run a fresh expansion pass over every observable perspective; new findings become rows; the walk stops only when that pass files nothing. Only the user's explicit stop ends it earlier. An open row resolves with a witness, or stays open with its blocking fact annotated on that row with `prd-note`; a blocker is never filed as a child row (gm-prd, Procedure).
- Unmet goal: keep working the graph. The host's stop condition is not observable; the continuation block in each reply carries the next row. A goal with no verifiable end state: do the next concrete step it names, report what changed, and never restate an unchanged blocked list.
- Denied gate or refused call: re-read the state the refusal names (`git_status`, `.gm/exec-spool/.dispatch-ledger.json`, the row file), fix it, retry once. Refused again with the same cause: work that cause. A `deferred: <residuals>; unchanged since <dispatch id>` reply is allowed only when no fix path remains, naming the external fact and the clearing action.

The harness cap is the only bound, read at run time, never a number written here. A refusal means that unit stays queued. Parallelize across as many waves as needed (gm-orchestrate, Standing pair).

## Standing preferences (every project, every run)
These hold in any project, with or without its own AGENTS.md. A project file may add rules; it may not drop these. Rules stated in Autonomy and Finish the work apply here unchanged.
- **Run shape.** Every gm run (the `gm` prompt) starts the standing pair in its first turn (gm-orchestrate, "Standing pair"): drain per file group in parallel, validate and fix each committed batch, and traverse in free slots once fewer than 20 rows are open. Harness-neutral; no workflow file needed. A run that closes no row is stalled: re-read the state each refusal names, fix it, retry each row once. A row still refused for the same cause is named in the witness log with its external fact and clearing action; the next run starts when that fact changes.
- **Retry discipline.** A row attempted in a run is not retried in that run. A row that does not close stays pending with its single blocking fact recorded, and the next round attempts it again on the route that fact allows. An attempt without a witness fixes the state its refusal names and retries once with a live witness. There is no blocked state and no `prd-block`: a row ends resolved (witnessed) or stale (witnessed refutation); otherwise its work stays open for the next launch.
- **Filing discipline.** One row per symptom. Before filing, check for an open row naming the same file and symptom; if one exists, add the evidence to it. Duplicate rows keep the backlog from draining.
- **Validation.** Rows on one file group run in sequence; agents may edit one shared file in parallel, each re-reading it right before its edit. Validation runs after the drain has committed its batch; a run that skips it is incomplete. The rollout files new rows only while fewer than 20 rows are open; at 20 or more the drain has priority and the run ends into the `gm-continue` handoff.
- **Closed rows go into the commit log.** A close must carry a commit whose body has all three trailers on their own lines: `Row: <id>`, `Witness: <dispatch id>` and `Status: resolved|stale`. `publish_on_origin` writes them from `row`, `witness` and `status`; a commit without all three is not a close. Its open file under `.gm/prd/` is deleted. The commit log is the durable record; `.gm/prd-log.jsonl` and `.gm/unknowns-log.jsonl` are gitignored runtime state that publishing never waits on.
- **Ownership.** A bundle owns the rows it is given; ownership never blocks a row. Only a real external fact, checked live in the run, is a blocker.
- **Backlog.** Issues met on the way are filed with `prd-add`, then taken by the lane owning the file. The walk ends at zero pending rows and a green tip, or at a blocker with its witness.
- **Witness.** A row closes only with a live dispatch id from its own run. The witness uses a SESSION_ID distinct from the resolver's (resolver `drain-<bundle>`, witness `verify-<row>`), and its dispatch id must be in `.gm/exec-spool/.dispatch-ledger.json`. A lane never closes its own row on CI it has not read. A witness refused for the resolver's own session is produced again from a separate SESSION_ID in the ledger, then the row resolves. A row never closes on a `superseded` or duplicate reason without a witness dispatch id.
- **Git.** Main only (Autonomy). Commit by explicit path after `scripts/check-staged-secrets.mjs` prints `RESULT: PASS`; the body carries `Row: <id>` on its own line. A commit refuses when other paths are staged; an amend is tried once, never looped. Push by full sha. Every push runs CI, and no push carries `[skip ci]`: pushes cascade updates to every machine, so they run promptly. Local iteration may skip CI only by an explicit local choice. Pins follow `main` tips.
- **Browser, builds, judgement.** Autonomy (Browsers; Publish first, test concurrently; Never ask about process) applies unchanged.
- **Codemode first.** Any multi-step operation that would take many tool calls is one `gm_codemode` script instead: loops over repos, clones or files with the check and the publish in the same body. Batch read-only lookups in one script; run independent writes in one script with a per-item result, so one failure never stops the rest. Prefer one gm verb per item inside a loop over shell pipelines. Measure a script's wallclock before repeating it, and cut the slowest step first (network fetch, then build, then CI). Automate end to end so the same work happens every run without a prompt.
- **Tools.** Code questions go to `callers` / `impact`, then `codesearch`; git and search use gm verbs, not the host shell's `git`, `grep` or `find` (Harness, Codeinsight first).
- **Transport.** gm-mcp is the only transport. Skills never write spool files, start the runner or run a CLI.
- **Environment.** No host-specific environment variables, hooks, settings files or harness-only features: gm works from the skill and its verbs alone.
- **Dream loop.** Dream-RSI only proposes. Nothing redeploys a strategy unattended.
- **No clones.** Never clone a managed repository to make a scratch copy, a fake worktree or a throwaway checkout, by any route (`gh repo clone`, `git clone`, a clone verb). Edit the shared checkout on `main` through its gm verbs, and publish from it with `publish_on_origin {repo_dir, row, message, paths, cwd}`. A collision is fixed by recovery: fetch, reapply the change on origin's tip, push. Falsified by: a clone of a managed repository made outside an explicitly named recovery step.
- **Pins.** Every push to a submodule advances the parent pin in the same run: the parent publishes the submodule path with `publish_on_origin`, so its gitlink equals that submodule's new `main` tip.
- **Blockers.** A blocker is annotated on the row it blocks with `prd-note`, and the row stays open. It is never filed as a child row, by `prd-add` with `blockedBy` or by `prd-block`.
- **Grep and proc-list.** A shell verb that invokes `find`, `grep` or `rg` is denied (`deviation.native-search-bypass`), including a pipe from process output such as `ps | grep`. Content and file search use `codesearch`; running processes are listed with `proc-list` and signalled with `proc-signal`.
- **Memory and fs_write.** `fs_write` is project-only: it refuses any path outside the cwd project root, and `allowOutsideRoot` never widens a write. Memory lives in the project under `memory/` (tracked; `memory/MEMORY.md` is the index), never in the user config directory. A file outside the project that must change is edited with the host editor and named in the report.

## 1. Harness
- Every verb: one `gm_codemode` call, `gm.<verb>({...})`, with `cwd` set. gm-mcp writes the request, waits, and returns the reply with `dispatch_id`. Transport: `spool-adapter.md`. Name any verb you cannot run, and why; never drop it silently.
- State lives on disk (`## State` in served instructions) and in response bodies, never in context. Phase mismatch: fresh `instruction` response. Bare state checks (phase, `prd_pending_count`, unknowns-pending) use `phase-status`; `instruction` only orients: fresh prompt, transition, drift, doubt about served prose.
- The session's first reply carries a `bootstrap` block (server version, runner liveness, pending row count, next pending row, checklist URI). Call `gm.status({cwd})` (daemon heartbeat, queue depth, lifecycle) or `gm.health({cwd})` (served build) only when that block is absent or stale.
- The runner belongs to gm-mcp. A dispatch that finds no live daemon sweeping its project makes gm-mcp start one and wait for the reply. A skill never starts, restarts, installs or second-guesses the runner. Liveness is read from `status`: a stale `daemon.heartbeat_stale` is confirmed by a `health` dispatch, never by a second start. A recent timestamp never proves liveness.
- A slow reply is busy, not dead. A dispatch still running returns a `resume_task`: resume it, never re-dispatch on silence. A `dispatch_orphaned` reply is re-dispatched only once `status` shows a fresh heartbeat.
- If `health` reports the runner binary absent, say so and stop. Never fetch or pipe anything yourself.
- The verb set belongs to the running build. A missing reply is not a verdict: gm-mcp reports unknown verbs as `error_code: unknown_verb`. Contention shows in `status` (`queue_depth`). Never conclude "verb unavailable" from silence.
- No raw `git` via the host shell (gated `deviation.bash-git-bypass`). Git body shapes and exec body rules (raw body, `timeoutMs`, ESM and `.cjs` scratch, truncation, MCP polling caps): `docs/verbs.md`.
- Batch independent dispatches in one tool-call block; one row per `prd-add`/`unknown-add` call. `{"items":[...]}` is rejected.
- Search-ban exception: a spilled reply (`reply_full_chars`, `spill_file`) is read with `gm_result`, or `fs_read` on the exact spill path. The native search tools, `find`, `grep` and `rg` stay off for content search.
- A `codesearch` with no `path`, `glob` or `path_glob`, or one you would repeat, runs in a subagent returning only located `path:line`. The orchestrator keeps locations, never match text.
- `transition` response's `phase_label` is internal, never a prompt name; the entered phase's served prose is its only instruction. Prompt reads (`prompts/get`): the initial `gm` prompt load and the `gm-continue` prompt handoff that ends every run, only. `gm_codemode` exposes no `prompts/get`, so a hop, PRD or orchestrate lane that needs its skill text reads `skills/<name>/SKILL.md` with `fs_read {"path":"skills/<name>/SKILL.md"}`: the same file the prompt serves.
- Token austerity: signal only, no narration or hedging. PowerShell input UTF-8 without BOM. SESSION_ID in every body. Never edit one file twice in a block.
- Every subagent prompt opens with the brick-wall opener and carries its own SESSION_ID. Parallelism: 1c. SESSION_ID minting: served `instruction` prose, "Subagent fan-out".
