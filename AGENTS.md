# AGENTS.md

## Purpose

This repository publishes the `gm-skill` release artifact. The installed `/gm` skill is `skills/gm/SKILL.md`. The agent drives the state machine; `rs-plugkit` serves it through spool verbs.

When the agent starts work, the agent shall first read `SKILLS.md`. When a request or an edited file matches a skill's frontmatter description, the agent shall read that `skills/<name>/SKILL.md`. If this file conflicts with the served `instruction` response, project configuration, or the applicable skill, the served response, configuration, or skill shall govern. Falsified by: `fs_stat` on `SKILLS.md` or on `skills/<name>/SKILL.md` returning an error, or a served `instruction` reply that contradicts the applicable skill.

## Glossary

- **walk**: one run of the gm state machine that the orchestrator drives to completion, bounded by the walk loop in `skills/gm/SKILL.md` (Section 1c).
- **hop**: one node traversal, performed by one `gm-hop` subagent for one principle node. Defined in `skills/gm-hop/SKILL.md`.
- **traversal**: the chain of hops along the graph's edges within one walk, bounded by the visited set and the depth limit.
- **node**: a vertex of `skills/dream-rsi/gm-graph.json`. A principle node is the only kind a hop visits; gate, terminal, phase and tension nodes are refused.
- **candidate**: an outgoing edge of the current node, a possible next node for a successor. Defined in `skills/gm-hop/SKILL.md`.
- **successor**: the next hop, spawned by a hop from one of its candidates, which receives the handover rhetoric.
- **worker**: a subagent in a walk that is a hop or a PRD row resolver, with its own SESSION_ID (`skills/gm/SKILL.md` Section 1c, Walk workers).
- **subagent**: an agent started with the Agent tool. A worker is a subagent that a walk launches.
- **slot**: one unit under the concurrency ceiling, occupied by a launched subagent until it completes. A freed slot is refilled while independent work remains.
- **row**: one PRD entry, identified by its id and held as pending or resolved. `prd-resolve` closes it with a witness.

- `skills/gm/SKILL.md` owns agent workflow and tool routing.
- `gm-config/` owns default phase prose, gate text, residual text, and the FSM graph. - `rs-plugkit/` is the WASM guest that implements orchestration, spool verbs, memory, and code search.
- `agentplug/` provides `agentplug-runner`, the native WASM host. It is the only supported loader.
- `gm-mcp/` wraps the spool write-and-poll cycle. The agent shall edit `gm-mcp/src/` and rebuild its committed bundle together. Falsified by: a delivery whose `gm-mcp/src/` diff lacks the matching bundle diff.

- `install.sh` and `install.ps1` install the skill and runner. Equivalent = same installed paths and same MCP registration command.
- `bin/gm-install.js` registers the MCP server as `node ~/.gm-tools/gm-mcp-server.mjs` (project `.mcp.json`: a `node -e` launcher resolving that path at start). The system shall never register an `npx github:` spec; its measured connect-timeout rationale is owned by `README.md` (MCP launch paragraph). Falsified by: a codesearch literal `npx github:` in `bin/` that matches a registration rather than the message at `bin/gm-install.js:28`.
- On Windows, when the installer invokes PowerShell, the installer shall do so through `runDirect` and `-File <install.ps1> spool`; `spawnSync` with `shell:true` loses argument boundaries. The installer shall rewrite the native Cursor, Gemini, and Codex MCP registrations, because `add-mcp` does not migrate their legacy entries. When updating Codex, the installer shall replace the full contiguous `[mcp_servers.gm]` TOML table span. Falsified by: a codesearch literal `runDirect` returning zero hits in `bin/` or `install.ps1` while a PowerShell spawn exists, or a Codex update that leaves a second `[mcp_servers.gm]` table in place.

The root is the published package. `package.json` lists release contents. When a skill change lands on `main`, `.github/workflows/skill-release.yml` shall publish it. The agent shall not assume a release succeeded without its workflow result. Falsified by: `fs_stat` on `.github/workflows/skill-release.yml` returning an error, or a release-facing completion report that cites no workflow run.

## Working with gm

The agent shall use the `gm` skill for engineering work. The agent shall prefer its MCP server. IF the MCP server is unavailable, THEN the agent shall use the documented spool fallback: write one complete request atomically, prefix every request number with a unique session id, and poll the matching response. While a fresh watcher is busy, the agent shall not start a second watcher. When a runner is stale or failed, the agent shall treat it as a defect in its owning source. The agent shall not bypass gm. Falsified by: a second watcher started while `scripts/triage/runner-status.sh` reports one busy, or a platform-native tool used where a verb exists for the same operation.

The agent shall use the verbs exposed by the running plugin for search, git, execution, memory, and state changes. When the matching verb exists, the agent shall not substitute a platform-native tool. The agent shall read runtime-state files directly only where the active skill permits it. `skills/gm/docs/verbs.md` is the verb inventory: every name, its body shape, and one example each. Falsified by: a Bash `grep`, `find` or `git` call in a session where `codesearch` or a git verb covers the same operation.

`codesearch` is the canonical search verb (`code_search` and `search` are aliases). `grep` (alias `rg`) is its exhaustive scan for "where is this string". Body shapes, aliases, output modes and regex-reading rules: `skills/gm/docs/verbs.md` (Code lookup).

For a structural code question (who calls X, what breaks if X changes, is X dead, a diff's blast radius), the agent shall dispatch `callers {symbol}` / `impact {symbol}` first. When that reply is an empty call graph, the agent shall confirm it with `codesearch` (alias `code_search`). Falsified by: a structural question answered with no `callers` or `impact` dispatch id, or an empty call graph with no following `codesearch` dispatch.

A `fetch` reply returns only its first `max_chars` bytes, and its spill note names the result JSON that holds the whole body. The agent shall raise `max_chars` above the page's byte length, or read that JSON with `gm_result`, before it concludes a needle is absent from the page. Falsified by: a needle that the full body contains reported absent at a `max_chars` below the body length.

A project shall list its generated and vendored trees for codesearch to skip in a `.codesearchignore` at its root (gitignore syntax, read in addition to `.gitignore`; a subdirectory may carry its own, scoped to its children), so that an unscoped query stays inside its 45 s budget. The system shall report dropped paths in `excluded_by_rule_summary`/`excluded_by_rule_count`, and shall keep gm-state exclusions (`gm_state_dir`, `agentplug_kv_cache`) out of `exhaustive`; any other rule exclusion clears it, as every real limit does. The per-path `excluded_by_rule` listing shall ride only when a rule dropped code, since every unscoped scan drops gm's own state.

The system shall treat the on-disk PRD and mutable state as authoritative. A walk shall complete only when the live state machine accepts `COMPLETE`, all required rows are completed, and `gm-continue` has checked for remaining work. Falsified by: a `COMPLETE` reply while `prd-list` with `{"status":"pending"}` still returns rows.

When the agent starts a subagent, the agent shall give the subagent its own session id and tell it to use the gm skill, with codeinsight (`callers`/`impact`) first. When work is independent, the agent shall parallelize it. Each shared surface (any file, ref, submodule pin or spool directory that two sessions can write) shall have one writer. A dispatch whose `cwd` is a submodule directory rewrites that submodule's tracked `.gm/last-dispatch-ts` and creates `.gm/dream-rsi/<session>/`, so the parent reports the submodule as modified. The agent shall restore those bytes and delete the new session directory right after such a probe, and shall confirm the restore with `exec_js`, since another dispatch re-dirties it. Falsified by: a parent `git_status` naming a submodule whose only changed path lies under its `.gm/`.

When a submodule commit changes, the same delivery shall update the parent pin to that commit. Falsified by: a subagent brief with no session id, two briefs that write one surface, or a delivered submodule commit whose parent gitlink is unchanged.

## Implementation rules

- Prose shall be self-explanatory: a prose sentence shall stay here only when deleting it loses a fact that names, types or signatures cannot state. Falsified by: a sentence whose deletion leaves every named path, verb and signature still stated elsewhere in the file.

- Synthetic = a test, mock or stub that bypasses the real entry point; placeholder = TODO/FIXME or a stand-in value; decorative glyph = a non-ASCII symbol the text does not need, so tracked prose (docs, skills, READMEs, changelogs, source comments) shall carry no em-dash or arrow used as decoration; a glyph that carries meaning (a quoted character, a detector pattern, a Unicode name) stays. The agent shall verify through the actual build and a live spool dispatch. Falsified by: a verification with no live dispatch id, a test or mock file in the delivered paths, or an em-dash or arrow in tracked prose that carries no meaning.
- Before each change, the agent shall state a falsifiable hypothesis and the live witness that would refute it. Falsified by: a change whose receipt names no hypothesis or no witness dispatch id.
- Every tracked text file shall be UTF-8 without a byte-order mark. Falsified by: a tracked text file whose first three bytes are `EF BB BF`.

## Triage scripts

`scripts/triage/` holds the one-call checks that cost the most time to improvise: `runner-status.sh` (watcher heartbeat age, pid liveness, plugin versions, exit 1 when dead), `runner-restart.sh` (stops runners by `/proc` exe and starts one detached watcher; `pkill -f` matches the calling shell and kills it), `check-pins.sh` (every submodule pin in HEAD exists on its remote; an unpublished pin breaks fresh clones), `run-failure.sh <owner/repo> <run-id>` (failing step and error lines of a GitHub Actions run, escape codes stripped), and `doctor.sh`, which runs the watcher check, the pin check and the latest failed CI run per release repo in one call. Before pushing a submodule bump, the agent shall run `check-pins.sh`. Before bumping the parent pin, the agent shall witness the submodule change through its own live entry point: one bump per verified change, never a bump made to test a fix. Falsified by: a submodule bump pushed with no `check-pins.sh` run, or a parent pin bump with no witness dispatch id.

## Verification and delivery

The agent shall verify the changed surface with its real entry point. For `rs-plugkit`, the agent shall build the guest and witness the changed verb through `agentplug-runner`. When `gm-mcp`'s source or input schema changes, the agent shall rebuild the bundle. When a release-facing change is made, the agent shall inspect the relevant workflow run and the resulting artifact. Falsified by: a changed verb with no witness dispatch id, a `gm-mcp` source diff with no rebuilt bundle, or a release-facing change with no workflow run cited.

Before a diagnostic override, the agent shall save the original property descriptor and record whether the target owns the property. The agent shall refuse an override unless the original state can be restored. New temporary own properties shall be set to `configurable: true`. In `finally`, an original own property shall be restored with its exact saved descriptor, and an inherited property's temporary own shadow shall be deleted. Before the final live witness, the agent shall verify the original property lookup and the absence of probe state. Falsified by: an override with no saved descriptor, or a final lookup whose descriptor differs from the saved one.

While performing git operations, the agent shall use the gm git verbs. The agent shall use `git_remote` to inspect configured remote URLs and the current branch's upstream without fetching or mutating state. Before delivery, the agent shall confirm that no residual remains (a residual is a pending PRD row, dirty path or unpushed commit), that pins are updated, and that the remote is verified. When the agent reports completion, the report shall cite a live witness reply. A commit message shall give the reason for the change, not restate the diff. Falsified by: a Bash `git` call in place of a gm git verb, a push with no prior `git_remote` reply, or a completion report with no witness reply.

The `gm-mcp` server shall compact every dispatch response before it crosses the wire; `gm-mcp/AGENTS.md` records which fields compact, which stay whole, and why. Falsified by: a dispatch reply on the wire that still carries a field `gm-mcp/AGENTS.md` lists as compacted.
