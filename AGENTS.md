# AGENTS.md

## Purpose

This repository publishes the `gm-skill` release artifact. The installed `/gm` skill is `skills/gm/SKILL.md`. The agent drives the state machine; `rs-plugkit` serves it through spool verbs.

When the agent starts work, the agent shall first read `SKILLS.md`. When a request or an edited file matches a skill's frontmatter description, the agent shall read that `skills/<name>/SKILL.md`. If this file conflicts with the served `instruction` response, project configuration, or the applicable skill, the served response, configuration, or skill shall govern. Falsified by: `fs_stat` on `SKILLS.md` or on `skills/<name>/SKILL.md` returning an error, or a served `instruction` reply that contradicts the applicable skill.

## Core invariants (memorize; checked before every turn ends)

1. Traverse: the gm-graph walk runs in every free slot. Each node pass files PRD rows from its discipline and nominates the next node from its own outward links, with a one-line rhetoric handed on.
2. Drain first: while pending rows exist, every free slot drains rows. Under 20 open rows, free slots traverse computer-science disciplines to file rows.
3. Orient (gm-orient): codesearch and codeinsight before any edit. Top 20 BM25, top 20 vector and top 20 commits, each with 3 live snippet lines. The database stores embeddings and ids only.
4. Resolve through six skills, each loading the next: gm-orient, gm-unknowns, gm-eliminate (JIT runs; new unknowns return here), gm-edit, gm-validate (JIT runs; failures return to gm-eliminate), gm-publish.
5. Unknowns are filed with `mutable-add` (status `unknown` while open) and closed with `mutable-resolve`. Elimination ends only when none are open.
6. Publish on main only: merge upstream, commit local work by explicit path, push, read CI. A failing job returns to gm-eliminate.
7. Plugkit runs 4 concurrent workers. A call over 15 s moves to background and frees its worker. A browser or GPU call takes a lease; browsers stay hot per project.
8. A subagent stopped by a network or API error is restarted for the same row, never resumed and never parked as blocked.
9. A row ends resolved with a witness or blocked with a named fact. A blocked row is not duplicated.
10. Success: rows always drain, and traversal refills them before they run out.

## Skill installs

An installed skill must be the file it is installed from, or the install must say it is not. `install.sh`, `install.ps1` and `bin/gm-install.js` materialise `~/.claude/skills/<name>` and `~/.agents/skills/<name>` from `<checkout>/skills/` (or `GM_SKILL_SOURCE_DIR`) as a link (a junction on Windows, a symlink elsewhere), so a source edit is served on the next dispatch. With no durable source (the release-tarball route, or a package under npm's npx cache, a `_npx` segment that npm can delete) the install copies, announces it, and records the mode in `<root>/.gm-skill-install-modes`. Against a checkout, a copy is drift even when its contents match.

A displaced install is parked under the dotted `<root>/.gm-skill-prelink/` (a plain sibling would be served as a skill), never deleted, because `.gm` state may be live. Deleting needs `--force-link` (bin/gm-install.js) or `GM_SKILL_LINK_FORCE=1`.

MSYS `ln -s` silently copies when symlink creation is refused, so on MINGW/MSYS/CYGWIN only `mklink /J` counts as a link. `install.sh` sets `MSYS_NO_PATHCONV=1` and uses `pwd -P`, since `readlink -f` is not portable. `install.ps1` unlinks links and never recurses into them. `docs/skills.html` describes the rule. `agentplug/crates/agentplug-runner/src/download.rs refresh_installed_skills` runs every 300 s in the daemon: it fetches `skills/manifest.sha256` from `main` (written by `scripts/build-skill-manifest.mjs`, checked by `.github/workflows/skill-release.yml`), re-fetches each changed file, installs new skills into gm-managed copy roots, skips a source-linked install, and parks stale files and retired copies. Falsified by: editing `skills/<name>/SKILL.md` and not seeing the edit at `~/.claude/skills/<name>/SKILL.md`, or `node bin/gm-install.js --check-skills` printing `DRIFT`.

## Glossary

- **walk**: one run of the gm state machine, driven to completion by the walk loop in `skills/gm/SKILL.md` (Section 1c, Routing).
- **hop**: one traversal of a principle node by one `gm-hop` subagent (`skills/gm-hop/SKILL.md`). **candidate**: an outgoing edge of the current node. **successor**: the next hop, spawned from a candidate, which receives the handover rhetoric.
- **traversal**: the chain of hops within one walk, bounded by the visited set and the depth limit.
- **node**: a vertex of `skills/dream-rsi/gm-graph.json`. Only principle nodes are visited; gate, terminal, phase and tension nodes are refused.
- **subagent**: an agent started with the Agent tool.
- **worker**: a walk-launched subagent that is a hop or a PRD row resolver, with its own SESSION_ID (`skills/gm/SKILL.md` Section 1c, Routing).
- **slot**: one unit under the concurrency ceiling, held by a launched subagent until it completes. A freed slot is refilled while independent work remains.
- **row**: one PRD entry, held as pending or resolved. `prd-resolve` closes it with a witness.

## gm-config

- `gm-config/` is a submodule. In a fresh checkout it is an empty directory, and `gm-config/gm.config.json` does not resolve, until the `git_submodule_update` verb with `{"path":"gm-config"}` runs (README.md, Install).
- `gm-config/gm.config.json` fields carry no inline `_comment` keys; rationale lives here. `version` gates the schema. The file IS the workflow definition that `crate::config::resolve` pulls on the debounce in `sync.debounce_ms` (`shallow` fetch; code default `DEFAULT_DEBOUNCE_MS` in `rs-plugkit/crates/plugkit-core/src/config_sync.rs`). It reproduces stock gm behavior unmodified until edited.
- `instructions.keys` name per-state prose files under `instructions.dir`, resolved project-vendored first, then this repo's cache, then the compiled default.
- `fsm.graph` and `fsm.predicates_reference` are the state machine as data. `gates.predicate` shall name only a predicate generated into `predicates_reference` from the same registry the code dispatches on; a condition outside that registry shall use a jit hook under `fsm.hooks_dir` instead.
- `messages.gates_dir` and `residual_dir` are operator-editable denial and residual text; editing them never changes when a gate fires.
- `memory.embed_dim` is compile-time coupled to the baked-in model weights. Changing it shall invalidate every stored vector through an explicit drop-if-mismatch path, never silently. `memory.tencentdb_backend.vectors_db_dims` is independent of `embed_dim`: it matches whichever TencentDB-compatible provider produced the indexed content, never gm's own embedder.
- `memory_sync.*_budget_ms` bound one `memory_md.rs::sync_index` pass. A pass that cannot finish shall record a `:partial` digest and converge across repeated dispatches rather than block one.
- `rssearch.table`/`index` and the `git_commits`/`code_chunks` equivalents shall accept only `[A-Za-z_][A-Za-z0-9_]*`, since they interpolate into SQL.
- `scoring.*` has two fusions. `recency_floor`, `cos_floor`, `dedup_jaccard_threshold` and `half_life_ms` govern recall's cosine-times-recency score. `bm25_k1`, `bm25_b`, `fusion_rrf_k`, `fusion_identifier_boost` and `fusion_vector_list_weight` govern codesearch's BM25 plus vector RRF fusion.
- `claim_audit.extra_*` shall append to the built-in defaults and never replace them. `cache.*` budgets are per namespace, so one greedy consumer cannot evict another's entries.

Falsified by: a `rssearch.table` or `git_commits`/`code_chunks` name containing a non-identifier character that a live dispatch accepts; a `memory.embed_dim` change that leaves stored vectors in place (codesearch `embed_dim` in `rs-plugkit/crates/` must show a drop-if-mismatch branch); a `claim_audit.extra_*` value that replaces a built-in default.

## Triage scripts and pin bumps

`scripts/triage/` holds the one-call checks; each script's header states its usage and output (`scripts/triage/runner-status.sh` exits 1 when dead, `scripts/triage/doctor.sh` exits 1 when any check fails). `.github/workflows/bump-pins.yml` runs `scripts/bump-pins.sh` on every push to main, on each submodule release, and hourly, and commits the advanced pins to main with `[skip ci]` in the subject, so the pin commit starts no CI run of its own. Each attempt resets to `origin/main`. A rejected push recomputes every pin on the new base, never skips one. A target is gated when its tip has a non-green release, publish, build or wasm run; an unreadable gate holds it. Each target's own release-path runs gate its advance, and `scripts/triage/check-pins.sh` runs on the candidate before the push. The commit body names the bump run. A manual submodule bump still runs `scripts/triage/check-pins.sh` before its push. Falsified by: a green bump run whose parent gitlinks differ from the remote main tips, a bump commit with no passing `scripts/triage/check-pins.sh`, or a bump commit with no bump run id.

## Verification and delivery

The agent shall verify the changed surface with its real entry point. For `rs-plugkit`, the agent shall build the guest and witness the changed verb through `agentplug-runner`. When `gm-mcp`'s source or input schema changes, the agent shall rebuild the bundle. When a release-facing change is made, the agent shall inspect the relevant workflow run and the resulting artifact. Falsified by: a changed verb with no witness dispatch id, a `gm-mcp` source diff with no rebuilt bundle, or a release-facing change with no workflow run cited.

Before a diagnostic override, the agent shall save the original property descriptor, record whether the target owns the property, and refuse any override whose original state cannot be restored. Temporary own properties are `configurable: true`. In `finally`, an original own property is restored with its saved descriptor and an inherited property's temporary shadow is deleted. Before the final live witness, the agent shall verify the original lookup and the absence of probe state. Falsified by: an override with no saved descriptor, or a final lookup whose descriptor differs from the saved one.

While performing git operations, the agent shall use the gm git verbs, and `git_remote` to inspect remote URLs and the upstream without fetching or mutating state. Work stays on `main` in every repository this agent touches; no branch holds work in progress. A collision (`conflicted: true`, an unmerged `UU` path, or a `.git/MERGE_HEAD`) is resolved and landed on `main` in the same turn, never parked. ## Live validation interfaces

- `node scripts/triage/dispatch-verb.mjs <verb> --cwd <project> --raw <body>` dispatches any spool verb and prints its reply and the latency. It reaches verbs the MCP table does not expose, such as `crawl`. It touches only the local spool.
- `agentplug-runner selfcheck-update-probes` reads the release channel for the runner, every loaded plugin and the skill manifest, through the daemon's own functions. Its only write is the skill manifest cache.
- `node <toolsDir>/gm-mcp-server.mjs self-update-status` prints the channel cache: the stored etag, the digest, the time of the last unconditional fetch, and the outcome of the last check. `self-update-now` forces a check.
