agentplug-runner self-update deadlock, fixed (commit 930b3e3, agentplug main): a promoted runner previously kept running from its staged .new executable image for its whole lifetime after takeover -- Windows locks a live process's own backing executable file, and run_takeover() only called promote_staged_exe_to_canonical() (copies bytes onto canonical) then continued in-process via run_daemon_body(), never re-execing from canonical. Every later self-update recomputed the same <canonical-base>.new staging path regardless of what path the process was actually running from, so a stuck process's own lock collided with its own next update attempt forever, failing download_and_verify's final fs::rename with 'Access is denied (os error 5)'. Fixed two ways: (1) run_takeover now spawns a fresh child from the canonical path and exits after a successful promotion, releasing the lock; (2) stage_runner_self_update in download.rs detects when current_exe() is itself already .new-suffixed and stages to a disambiguated .new2 suffix instead, so a process still running the old buggy code can stage forward without colliding with its own locked file. This supersedes the earlier memo describing 'always stages to <exe>.new first' as if that were simply the design -- it was actually an unbounded-retry deadlock for any process that got stuck running from .new.
