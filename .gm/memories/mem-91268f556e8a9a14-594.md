GitHub release redirects no longer carry the tag: releases/latest/download/<asset> now 302s to release-assets.githubusercontent.com with a signed URL and no /releases/download/<tag>/ segment, so a version derived from the redirect fails while api.github.com is rate-limited or proxied. The runner installs under a latest-sha256-<16 hex> marker, refreshes by comparing the sha256 sidecar, and stages a runner self-update only when the staged binary reports a newer semver than the running one, so a locally built runner at the released version number is never overwritten by the release's bytes.
