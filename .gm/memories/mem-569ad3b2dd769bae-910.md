WASI shim default for unknown fd_prestat_get/fd_prestat_dir_name/path_open/path_filestat_get calls must return BADF (errno 8), never NOTSUP (52) or any other stub value. WASI runtimes enumerate preopened filesystems via fd_prestat_get starting at fd=3, expecting ESUCCESS=0 (preopen exists) or BADF=8 (no more preopens, stop probing). NOTSUP=52 is treated as fatal and libsql-ffi 0.9.x specifically panics the wasm caller on it, silently killing the gm plugkit watcher mid-dispatch with no further processing. Explicit shims needed for the common probe set: fd_prestat_get, fd_prestat_dir_name, fd_close, fd_fdstat_get, fd_fdstat_set_flags, fd_filestat_get, fd_seek (write 0 to newoffset_ptr, return 0), fd_read (write 0 to nread_ptr, return 0), path_open (BADF), path_filestat_get (BADF), poll_oneoff (0), sched_yield (0). Witnessed across rs-plugkit v0.1.456-459 fixing a full memorize/recall dispatch panic.
