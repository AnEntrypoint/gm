rs-plugkit ragconfig.rs no-comments sweep pattern: when converting a struct's doc comments to self-explanatory code, first check every field/method for EXTERNAL callers across the whole crate before renaming -- a field read only via a sibling struct's own copy (e.g. vecns.rs's independent QueryBudget/RecencyParams project ragconfig's ScoringConfig/QueryBudgetConfig fields by value, not by calling ragconfig's own methods) is safe to rename freely, but a field or method called directly from an off-limits file (a concurrent agent's active directory, or any file outside the task's stated scope) must keep its exact name -- discovered live when a QueryBudgetConfig::pool rename compiled clean initially (grep for '.pool(' inside ragconfig.rs missed it) and only failed cargo check once the crate-wide call site in wasm_dispatch/verbs.rs surfaced, requiring a revert. Lesson: grep the SYMBOL NAME across the whole src tree before a rename, not just within the target file, even when a local compile looks clean partway through a multi-file edit.
