gm jit-hook example.js semantics: .gm/instructions/hooks/<name>.js is a plain exec_js script the FSM orchestrator runs automatically at a gate's evaluation, wrapped in an async function body before running (same wrapping every exec_js dispatch gets, per agentplug-host's build_command). Gate result comes from an EXPLICIT return -- a bare trailing expression statement (e.g. `foo();` as the last line) is a discarded statement value, not an implicit return, exactly like a normal JS function body. `true` passes the gate; anything else (false, a thrown error, a non-boolean return, a missing return, a missing/unreadable file) fails it CLOSED, never open. Wire a hook into gates.json via a GateDef's `hook` field (path relative to hooks/) and `hook_mode` (hook-only replaces the compiled predicate entirely, both requires both the compiled predicate AND the hook to pass, default predicate-only ignores the hook file). The shipped example.js denies until .gm/ship-approved exists, a made-up project-specific condition gating human/CI sign-off before CONSOLIDATE proceeds.
