A gm performance win is not delivered when it is merged and pushed, only when the running runtime actually serves it. Two independent instances found in one session, both of which had green builds, clean worktrees and pushed pins while reaching zero users. First: the entry.md prose core/tail split plus per-session unchanged-marker landed as rs-plugkit 720e606, but the shipped gm.wasm 0.1.1282 does not contain that commit at all (grep for instruction_unchanged in the binary returns nothing, no instruction_hash field appears in any response, and a prompt of entry-extended is silently ignored), so the on-demand tail is unreachable until the cascade republishes. Second: the rs-codeinsight 40 percent speedup was verified real at the crate level (byte-identical deterministic output, ~203ms against a 343ms baseline) but the running daemon does not load codeinsight as a plugin at all, returning counts_error unknown_plugin and counts_unavailable true, so the overview stays degraded regardless. Definition of done for perf work in this repo must include a runtime-serving check that the live path actually returns the improved behavior, not a build plus a push.
