gm cascade pipeline full step sequence: push to any rs-* sibling triggers cascade.yml, which triggers rs-plugkit's release.yml, producing a single plugkit.wasm (published to npm plugkit-wasm and to plugkit-bin GitHub Releases), followed by a best-effort gm-metadata-sync commit, then publish.yml uploads a gm-skill-<version>.tar.gz GitHub Release using the automatic GITHUB_TOKEN -- no cross-repo mirror, no npm registry involved for gm-skill/gm-plugkit. gm.json.plugkitVersion is informational-only, never a functional pin -- nothing reads it; the real runtime pin is gm-plugkit/plugkit.version, always resolved fresh by install.sh/install.ps1 at install time, and publish.yml's drift-check no longer gates on it. Every downloaded wasm/binary artifact is sha256-verified against the sha published alongside that exact resolved release by install.sh/install.ps1, always using a fresh fetch rather than a locally-committed value; floating past the committed pin never weakens verification. Submodule pointers auto-sync via .github/workflows/submodule-sync.yml on a 30-minute schedule. The three agentplug-* wasm-plugin repos (agentplug-bert, agentplug-libsql, agentplug-treesitter) share one reusable release workflow hosted in rs-plugkit (wasm-plugin-release.yml, workflow_call) parameterized per plugin. agentplug is a separate parallel pipeline that CONSUMES the cascade's output (decoupled at the plugkit-bin release artifact), not a stage inside the cascade itself.
