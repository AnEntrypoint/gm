rs-plugkit config.rs SCHEMA_VERSION/MIN_READABLE_SCHEMA_VERSION rationale: SCHEMA_VERSION bumps only for a breaking shape change; a config declaring a version above it is rejected loudly rather than parsed on the hope unknown fields are additive, since a newer config likely relies on semantics this build lacks. MIN_READABLE_SCHEMA_VERSION is a RANGE not an equality (same reason Policy uses serde defaults instead of deny_unknown_fields): in an auto-updating fleet, an exact-match gate meant a routine config-repo version bump instantly dropped every not-yet-updated client to compiled defaults -- a fleet-wide outage triggered by a routine publish. A config newer than the build is now accepted with a warning (every field has a default, unknown keys are surfaced not fatal) since applying the recognized subset is strictly closer to author intent than ignoring the whole file.
