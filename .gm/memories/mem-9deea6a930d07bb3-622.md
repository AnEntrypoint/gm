gm.wasm linear-memory growth source: host_kv_query returns a whole kv namespace as one JSON array string and code_index load_manifests parses all of it, so a large codeinsight manifest namespace grows the gm Store by several times its on-disk size and wasm memory never shrinks. Host side this is bounded by the per-plugin ceiling (gm 384MB default, the Store is dropped after the dispatch that grew it and re-instantiated in milliseconds from the mapped module). The lasting fix is in rs-plugkit crates/plugkit-core/src/code_index.rs: read manifests per key or page the query instead of one whole-namespace host_kv_query.
