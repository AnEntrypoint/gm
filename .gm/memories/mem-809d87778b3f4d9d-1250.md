rs-plugkit config.rs 4-tier config resolution chain design rationale (ProjectVendored -> ProjectRepoSpec -> UserRepoSpec -> ImplicitDefaultRepo -> BuiltinDefault): generalizes prose.rs's 3-tier chain, adding a user-wide tier prose.rs lacks. Unlike prose.rs's opaque markdown blob (cannot be malformed), config carries a versioned parseable schema needing a total parser + explicit failure reporting. Single gm.config.json file (not a directory) chosen deliberately: a directory forces file-ordering/key-collision/stray-file decisions a single file avoids, and partial override is already expressible as a partial JSON object via deep_merge. Deep-merge is strictly WITHIN one tier (tiers never merge with each other, first match wins whole): object+object recurses, any+non-object replaces outright, array+array replaces (never concatenates -- arrays are ordered whole values like an allowlist or phase order, and element-wise merge would make list order load-bearing unpredictably), explicit JSON null in override replaces with null (a deliberate authored 'unset this' value, distinct from omitting the key). Merge only applies to an already-parsed+version-checked config; a malformed/unknown-version tier is Rejected, never silently merged as empty.
