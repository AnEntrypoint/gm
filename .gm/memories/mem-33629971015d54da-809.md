rs-plugkit Graph::deviation_severity_warnings() rationale: reports deviation-severity overrides this build cannot honour, as NON-FATAL warnings. Deliberately not part of validate(). A validate() problem REJECTS the whole graph and falls back to the compiled default, right for a referential break (an edge to a nonexistent state cannot be traversed) -- but wrong here, since a single mistyped severity key would discard every unrelated customisation in the file (states, edges, gates, thresholds) and silently weaken the FSM far beyond the one wrong line. Both failure modes here are already self-limiting because effective_severity falls back to the registry default for an unknown kind or unparseable value, so the graph stays perfectly usable. Same reasoning and non-fatal treatment as unknown_policy_keys.
