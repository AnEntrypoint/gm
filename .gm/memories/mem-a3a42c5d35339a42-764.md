memorize-fire on plugin gm is bound by the generic DISPATCH_CALL_DEADLINE_SECS (40s, agentplug/crates/agentplug-host/src/registry.rs) even though its embedding work routes through bert (which itself gets a 600s BERT_DISPATCH_CALL_DEADLINE_SECS carve-out) -- the outer gm dispatch is the one that actually times out under memory pressure or a cold embed cache, not bert's own call. registry.rs already exposes an escape hatch: caller_supplied_deadline_secs(body) reads a top-level deadline_secs field in the spool JSON body (ceiling 3600s) and uses it instead of the plugin default when present. Passing {"deadline_secs":120} (or higher) in a memorize-fire/recall/codesearch/instruction body when the default 40s is tight raises the ceiling without any code change.
