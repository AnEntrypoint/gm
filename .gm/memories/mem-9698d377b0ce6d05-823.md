gm en-masse memory mechanism: the daemon used to instantiate all six plugins (gm, libsql, bert, treesitter, oxibrowser, crux) for every project on its first dispatch, and libsql/oxibrowser/crux get one Store per project, so N projects cost N private Store sets whether or not they used them. Only gm is eager now; every sibling is instantiated on its first host_plugin_call or host_vec_embed (watcher-log event plugin_lazy_loaded). A wasm linear memory never shrinks, so a per-plugin ceiling evicts a Store the dispatch left oversized (plugin_store_linear_memory_ceiling_mb, event plugin_store_evicted_linear_memory_ceiling); bert measured 144MB idle, 283MB after one small codesearch index pass, 412MB mid-index, so its ceiling is 768MB and the process gate 768MB private sits above the measured 262MB post-index baseline.
