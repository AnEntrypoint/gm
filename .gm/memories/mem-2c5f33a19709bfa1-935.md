Disjoint-history submodule republish pattern: a repo's remote main can be a single squashed initial commit whose source tree is byte-identical to a local clone that still holds the original long history under a different root commit. git merge-base --is-ancestor reports no ancestry in either direction, so a push is rejected as non-fast-forward and the tempting fix is a force-push, which would discard the remote commit and is a one-way door needing explicit consent. The non-destructive resolution is a merge with allow-unrelated-histories from the remote root into local, which makes the push a plain fast-forward and keeps both lineages reachable. Verify the merge is content-neutral by comparing tree hashes: git write-tree after resolving conflicts should equal the tree of HEAD, proving the merge adds lineage only and changes no file content. Conflicts appear as add/add and are confined to files touched since the divergence.
