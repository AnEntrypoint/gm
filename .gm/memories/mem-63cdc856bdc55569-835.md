agentplug-host browser.rs run()/session_new()/session_close() had a TOCTOU race: sessions_map's lock was released between the reuse-check and launch_chrome (real Chrome spawn), so concurrent dispatches for the same cwd+session_id key each independently launched Chrome -- root cause of a real ~20-Chrome-on-about:blank incident. A project never writing .gm/exec-spool/.session-current makes every browser dispatch resolve to the identical empty session_id, so ANY concurrent browser-verb load on that project collides on one key. Fixed via a per-key session_lifecycle_lock_for_key held across each function's full critical section (reuse-check through insert). Live-reproduced in a standalone thread::spawn harness before landing: original logic gave 20 distinct launches under 20 concurrent same-key calls, fixed logic gave exactly 1.
