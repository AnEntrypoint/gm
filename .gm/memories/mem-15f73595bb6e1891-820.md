gm-method: mutable-resolve's auto-memorize was silently dead-ending. handle_resolve in orchestrator/mutables.rs called the bare memorize::fire() function, which only writes a markdown file into .gm/exec-spool/in/memorize/<n>.md -- a spool inbox nothing in the crate ever reads, embeds, or ingests. The response's memorize_spool field looked like proof of persistence but was not. Fixed by calling memorize::handle_fire() instead, the exact function the memorize-fire verb itself calls, which writes through memory_md::write_memory into .gm/memories/<key>.md, embeds it, and runs the same agents_drain_obligation back-pressure check. Lesson: a verb's response field naming a spool/file path is not itself evidence of durable persistence -- trace the actual consumer of that path before trusting it as a completion signal.
