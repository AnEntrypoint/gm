## Resolved mutable: mut-wasm32-thread-availability

rs-plugkit Cargo.toml targets wasm32 with candle-core/candle-transformers (Device::Cpu only, no cuda/wasm-simd feature flags enabled), libsql-ffi wasm32-wasi-vfs feature, tokenizers unstable_wasm feature -- no wasm32-wasip1-threads target, no std::thread usage anywhere in plugkit-core/src grep. Real OS-thread parallelism is not reachable on this wasm32 target without a threads-proposal toolchain rs-plugkit does not use. Conclusion: batching via candle's native tensor batch dimension (single-threaded SIMD-vectorized matmul across a batch) is the correct lever, not thread-based parallelism -- feeds directly into batch-embed-model-forward row.
