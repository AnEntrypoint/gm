During a /loop or gm-skill session, inspect spool outputs and repo state with dedicated tools, never Bash+cat/ls/grep: Read for spool out-files and .gm/* state (not cat|head -c N), Glob for file listings (not ls|grep), Grep for code search (not grep -rn). Never chain sleep N; cat X for polling -- it fires once and can miss the event; either dispatch the next verb instead of polling (watcher responds in ~50ms typical), or use an endorsed condition-poll loop (until <check>; do sleep N; done), which IS allowed for external state like CI runs or npm publishes. This discipline holds even mid crash-investigation -- the debugging-bread-and-butter reach for ls/tail/cat/find has tool equivalents (Glob, Read+offset) and 'use the right tool when calm' is not the rule; 'use the right tool, full stop' is.
