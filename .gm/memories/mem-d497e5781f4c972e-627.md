Bootstrap/install paths for gm/plugkit must not default to @latest on every run -- read the pinned version from the committed manifest first, use that pinned version, and only fetch @latest when an explicit version-check detects a newer release (then download, sha-verify, update the manifest, use the new one). Defaulting to @latest on every bootstrap forces a registry check every session and loses determinism; pinning gives reproducible state while an explicit upgrade path still allows updates. This is the general shape gm's current install.sh/install.ps1 + sha256-verification-against-fresh-fetch design already follows.
