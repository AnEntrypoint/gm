rs-plugkit Policy.fresh_prompt_resets_phase field rationale: whether a fresh user prompt resets a stuck or finished chain back to the initial phase. Two heuristics live in instruction: a fresh prompt on a non-initial, non-terminal phase with zero pending PRD rows reads as a stalled chain and resets; a fresh prompt on the terminal phase starts over. Both are right for gm where a new prompt means new work, but this is the only place a READ-shaped verb WRITES turn state -- a spec whose phases model something longer-lived than one prompt (a release train, an approval queue) would find its phase silently rewound by a question. Default true preserves gm's existing behavior exactly.
