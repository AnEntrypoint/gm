Zero-branches audits must use `git ls-remote --heads origin`, never `git for-each-ref refs/remotes`. for-each-ref only sees refs THIS clone has already fetched, so a branch pushed from another clone/machine and never fetched locally is completely invisible to it -- the audit reports clean while a real branch sits on origin. Live-hit 2026-07-28 consolidating gm + submodules: a for-each-ref sweep across all 8 repos reported zero stray branches, but a follow-up ls-remote sweep caught rs-plugkit's origin still carrying refs/heads/claude/project-structure-mermaid-7pwny0 with 5 unmerged commits including a real source fix (20c2695, prose.rs honoring messages.gates_dir/messages.residual_dir in the config-repo tier). Deleting on the strength of the for-each-ref reading alone would have destroyed that work. Corollary discipline that caught it safely: before ANY branch delete, gate on containment against the PUSHED remote (git merge-base --is-ancestor <ref> origin/main exit 0 AND git log --oneline origin/main..<ref> empty), scripted with an explicit abort path, then re-verify post-delete with git branch --contains <tip> -- never trust a push/delete summary line. Second corollary: `git branch -d` refusing with 'not fully merged' can be a stale-UPSTREAM artifact (it compares against the branch's own now-deleted refs/remotes upstream, not against main), so it is not by itself evidence of unmerged content -- prove containment independently against main AND origin/main, then -D.
