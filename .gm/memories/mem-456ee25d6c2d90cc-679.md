rs-plugkit residual_scan_fired predicate uses ONE global marker (.gm/residual-check-fired), not per-edge/per-phase, since residual-scan asks a single stop-window-scoped question. Real known weakness: freshness is enforced entirely by clear_marker("residual-check-fired") in lib.rs session_start/session_end/prompt_submit hooks -- where those hooks do not run, the marker never clears and the predicate reports an arbitrarily-old scan as current (observed live with a marker ten days stale). Fails OPEN when hook delivery is absent. A mtime-vs-session-start comparison would degrade gracefully but the marker carries no timestamp; adding one is a wire-format change, not yet done.
