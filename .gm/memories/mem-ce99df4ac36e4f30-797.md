Windows Git-for-Windows MSYS2 stackdump caveat (confirmed live 2026-09-01): sh.exe, bash.exe and du.exe intermittently write a <tool>.exe.stackdump when many git or shell subprocesses spawn in quick succession (about 15 sequential git or submodule commands reproduce it). The cause is a fork() emulation failure inside msys-2.0.dll, an upstream MSYS2 DLL-rebase collision under concurrent spawn. *.stackdump is gitignored at the root and in every submodule; a fresh sighting is residual junk to delete, never a sign the git or submodule operation failed. If a specific dispatch such as install.sh or a spool boot fails because of it, that failure still gets its own PRD row and a root fix (serialize the spawns, or move the script off sh where the crash rate is unacceptable), never a blind retry.
