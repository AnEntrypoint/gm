gmsniff read daemon-registry.txt/daemon-status.json from ~/.gm-tools/ across registry.js/index.js/cli.js/server.js -- a directory the shared agentplug daemon stopped writing those two files to once it migrated live state to ~/.agentplug/, so gmsniff silently answered project-discovery/daemon-status queries from frozen dead data (only usable via a separate readdir fallback). Fixed by adding an AGENTPLUG_DIR constant and routing every daemon-registry/daemon-status read through it, leaving plugkit.version/gm-plugkit.version on GM_TOOLS_DIR since those still genuinely live there. LESSON: a daemon/runtime migrating its state-file location leaves every consumer of the old path silently stale until audited -- compare file mtimes, not just existence, to catch it.
