gm SKILL.md browser session persistence rationale (agentplug commit 912f396): the Chrome process launched by session new (or any dispatch's first-touch of a session_id) stays alive across every subsequent dispatch sharing that session_id -- no longer killed at the end of each dispatch, avoiding ~5-10s Chrome-boot overhead on reuse. Ends via explicit session close/reset, auto-reap after session_idle_timeout_ms (default 30min), or the daemon exiting. The on-disk --user-data-dir profile under .gm/browser-chrome-profile-<session_id>/ survives even a session close (only the process dies), so a later session new under the same id still gets a warm profile.
