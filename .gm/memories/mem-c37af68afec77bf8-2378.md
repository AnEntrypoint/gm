How to locally compile-verify an rs-plugkit source edit (a real local witness IS available -- do not conclude 'CI is the only build surface'). WORKING COMMAND, verified live 2026-07-29, exit 0 in 4.58s from C:/dev/gm/rs-plugkit: `cargo check --target wasm32-wasip1 --no-default-features --features slim --lib`. This is the SLIM variant, which is what gm actually ships and runs (agentplug-runner loads plugkit-slim.wasm), and it needs no model weights at all, so it works in a fresh checkout with zero setup. THREE MISTAKES that make a local check look impossible when it is not: (1) WRONG TARGET -- using wasm32-unknown-unknown instead of wasm32-wasip1 produces four bogus `error[E0433]: cannot find module or crate ignore` failures at code_index.rs:335/344/378 even though `ignore = "0.4.30"` IS declared in Cargo.toml; those errors are target-resolution artifacts and vanish entirely under wasm32-wasip1. (2) MISSING --no-default-features --lib -- CI always passes both (see .github/workflows/build.yml lines 58/61/64 and release.yml 116/162). (3) WRONG PACKAGE NAME -- the crate is NAMED `rs-plugkit` while living at crates/plugkit-core, so `cargo check -p plugkit-core` fails with 'package ID specification `plugkit-core` did not match any packages'; either use `-p rs-plugkit` or omit -p entirely since it is the sole workspace member and the default-member. NON-SLIM VARIANT: `cargo check --target wasm32-wasip1 --no-default-features --lib` fails on a fresh checkout with exactly ONE error -- `couldn't read crates/plugkit-core/src/../../../weights/bge-tokenizer.json` at embed.rs:41, an include_bytes! of the embedded bge model tokenizer. That is expected, not a defect: weights/ is gitignored by design (.gitignore:45) and CI fetches it by running `bash scripts/fetch-weights.sh` before every check/build step. That script downloads BAAI/bge-small-en-v1.5 model.safetensors and tokenizer.json from HuggingFace with pinned sha256 verification. To verify the non-slim path locally, run that script first; otherwise prefer the slim check, which covers the shipped artifact anyway. METHOD LESSON: when a local build fails in a way that seems to force reliance on CI, check the project's own workflow file for the exact target/feature/package triple BEFORE concluding the local surface is unusable -- reading .github/workflows took one grep and turned five errors into zero.
