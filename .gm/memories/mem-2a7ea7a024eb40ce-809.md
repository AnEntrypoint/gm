rs-plugkit predicate_table design rationale: name/description/evaluator declared together in ONE table type PredicateFn=fn()->bool, deliberately not three separate lists. History: used to be two independent lists (known_predicates() for the generated reference, and a match in predicate_result for behavior) and they drifted -- the match dispatched 8 predicates while the list published 6, so fsm_vendor generated a predicates.md that contradicted the default graph.json it generated beside it, while asserting in its own text that it could not drift. The single-table design makes that class of bug unrepresentable: adding an evaluator requires also supplying the name and description. The evaluator is a fn pointer rather than a closure so the table stays plain const-shaped with no allocation or lazy init.
