config_sync.rs's ensure_current(src, debounce_ms) was purely debounce-timer-based (default 15min via GitRepoFetcher::default()) with no on-demand refresh path -- a config-repo push could sit unpicked-up for the full debounce window. Fixed in rs-plugkit: config::resolve_forced(project_root) calls resolve_with using GitRepoFetcher::with_debounce_ms(0), which ensure_current's own debounce check (elapsed < required) can never satisfy with required=0, so it always does a real remote-ref probe. Also clears the short-lived RESOLVE_CACHE so the next plain resolve() call sees the fresh result. Wired as the config-sync-now spool verb (wasm_dispatch/verbs.rs). Dispatch it right after pushing a change to a config repo (project's own .gm/config.source.json target, or gm-config itself) to apply that change the same session instead of waiting out sync.debounce_ms.
