gm SKILL.md GL-error dedup history (resolved 2026-07-17, gm-plugkit source fix on AnEntrypoint/gm main): pre-fix window.__gmGlErrors capped at 40 raw OCCURRENCES ever per page load, so a GL error firing every frame filled the array within the first second and every subsequent browser dispatch for the rest of a many-minutes debugging session read back the exact same frozen entries, making a still-firing error look capped/stale/resolved. Fixed to a per-signature dedup table (draw-fn + error code + mode + count + instanceCount), capped at 40 DISTINCT signatures not 40 raw occurrences -- a recurring error updates its own entry's occurrenceCount/lastDrawCallIndex instead of being dropped once the old fixed-count cap filled. Each entry carries a captured stack (last 8 frames) from its first occurrence. window.__gmGlErrorTotalCount is a true cumulative counter independent of the 40-signature cap. If debug.gl.errors ever looks suspiciously static across dispatches spanning real wall-clock time again, check debug.gl.errorTotalCount first: a growing total against a static errors array length means a NEW dedup-adjacent bug, not a fixed one regressing.
