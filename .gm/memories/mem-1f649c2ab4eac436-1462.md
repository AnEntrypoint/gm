agentplug daemon.rs self-update handoff protocol, extended: the per-project .status.json heartbeat (write_project_heartbeat_with_queue_info in daemon.rs) now surfaces the daemon's own self-update state directly, previously visible only via manual daemon.log reading or ~/.agentplug/daemon-status.json (a file no served gm doc ever told an agent to check). New fields: runner_update_in_progress (bool) + runner_update_waiting_ms when staged_runner_awaiting_handoff() is Some -- a takeover is staged and mid-handoff right now, a dispatch landing in this window can legitimately return dispatch_orphaned, and the correct recovery is a bare re-dispatch of the exact same verb once .status.json's ts is fresh again, never a different recovery path. last_completed_runner_swap ({version, swapped_at_ts}) is the durable record from record_completed_runner_swap, now also copied into .status.json so an agent can diff it against what it last saw this session to notice served behavior (prose, gates, verb set) changed mid-turn without polling daemon-status.json separately. loaded_plugin_versions ({gm, bert, libsql, treesitter}) reports each loaded plugin's version string -- purely informational, since a plugin content-hash recompile evicts+rebuilds in-process without a process restart and never orphans a dispatch the way a runner takeover does, but still useful to diff for noticing gm's own behavior shifted. Landed in agentplug commit (this session, 2026-08-01).
