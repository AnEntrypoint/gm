rs-plugkit config.rs RepoFetcher trait + NoopFetcher rationale: RepoFetcher is deliberately NOT implemented in config.rs -- git fetching is another module's scope (config_sync::GitRepoFetcher). resolve_with takes an injected fetcher so it stays testable off-wasm and so callers that must not touch the network can pass NoopFetcher. This injection seam is also how the module shipped-but-inert for a while in practice: nothing constructed a real fetcher, so repo-backed tiers (2/3) never fired in production regardless of chain correctness -- resolve()/resolve_and_report() are the wired entry points that bind the chain to the real GitRepoFetcher. Implementors must be safe under the process-wide shared plugin instance: two concurrently-active projects can call refresh() at once; project-tier cache dirs are distinct paths but a shared user-tier cache dir can genuinely be hit twice concurrently, so an implementation needs its own locking or atomic publish (same reasoning gitignore.rs and legacy_reaper.rs each needed).
