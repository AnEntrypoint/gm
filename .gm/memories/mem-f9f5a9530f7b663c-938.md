gm-method: agentplug is a separate parallel pipeline from the plugkit-core cascade, decoupled at the plugkit-bin release artifact. The main cascade (rs-codeinsight/rs-search/rs-plugkit/gm push triggers) produces the wasm guest (plugkit-bin release, ~138MB with embedded bge-small model). agentplug's own CI (in AnEntrypoint/agentplug, agentplug-bert, agentplug-libsql, agentplug-treesitter) builds only the native host binary (agentplug-runner, 6 platforms) and sibling plugin *-bin releases -- none of them build or publish the gm wasm itself. agentplug-runner fetches the same plugkit-slim.wasm from plugkit-bin at runtime via a 600s poll, so a plugkit-core change flows through to every host including agentplug-runner with zero agentplug rebuild needed. An agentplug-host change (new native subsystem like browser/task) rebuilds only agentplug-runner, independent of the cascade -- the two pipelines never need to coordinate releases.
