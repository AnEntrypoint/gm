Every fsm-propose-override proposal of kind:"prose" expresses its named-technique content as attributed anchors, not paraphrase. An anchor is a compact reference to a well-known, well-attributed technique from real literature -- e.g. MECE (Barbara Minto) -- never a paraphrased description. Where the proposed prose lists more than one anchor and those anchors relate to each other, express the relation as a mermaid graph (flowchart with -.-> edges), not a flat list -- matching how gm-config's phase prose (specify.md, emit.md, state.md, sec.md, update_docs.md) already carries cross-anchor edges in its Preferences sections. Never invent an edge: state only a relation genuinely known from the cited literature (shared author, documented dependency, explicit see-also in the technique's own source). If synthesis surfaces a well-known, well-attributed technique missing from the phase's existing anchor list, add it with correct attribution and graph it in, never just append to a flat list. Never cite an external anchor-catalog website by name or URL; the anchor+author pair is the self-contained citation. This governs the content shape of every prose-kind self-reconfiguration proposal, not a one-time pass -- it applies every time fsm-propose-override composes proposed_text for a kind:"prose" override, for the lifetime of the project.
