agentplug-runner update-poll observability, autonomous self-update, and sideload protection (settled against real daemon.rs source, 2026-07-28). SELF-UPDATE IS FULLY AUTONOMOUS FOR BOTH HALVES -- an earlier AGENTS.md claim that the runner updates only the wasm it serves and never its own executable was WRONG and has been corrected in-tree. Proof read directly from agentplug/crates/agentplug-runner/src/daemon.rs: the main loop at line ~1447 fires `if last_runner_update_poll.elapsed() >= runner_update_poll_interval || take_forced_runner_refresh_request()` (interval from runner_update_poll_interval_secs, default 600 via `unwrap_or(600)` at line ~153), calls `crate::download::stage_runner_self_update()`, and on Ok(Some((staged, version))) stores it as `pending_self_update`. Then at line ~1467 a separate `if !any_work` idle-tick branch takes that pending update, calls `attempt_self_update_handoff(&staged, &version)` (defined line ~424), and on success calls `agentplug_host::close_all_sessions()` and RETURNS (the old process exits, having handed off to the new binary). So: staged in the background on a poll, swapped in on the next genuinely idle tick, no agent action, no bin/install.js re-run, no restart required. bin/install.js re-run remains a valid MANUAL path, not the only path. OBSERVABILITY: poll liveness is read from ~/.agentplug/daemon-status.json's last_plugin_update_poll_ts / last_runner_update_poll_ts (written at daemon.rs ~503, plus last_runner_update_poll_error at ~505), refreshed each plugin_update_poll_interval_secs / runner_update_poll_interval_secs tick. A null or stale value THERE is the live signal. The files .update-check-cache.json and .wasm-update-respawn-guard.json belong solely to the retired plugkit-wasm-wrapper.js JS host and are NEVER written by agentplug-runner -- their staleness once agentplug-runner is the active loader is expected, not a defect, and chasing them is a known false lead. SIDELOAD PROTECTION: a plugin whose installed .version marker is not real release semver (e.g. a hand-built 0.0.0-local-dev build) is never silently auto-overwritten; the daemon warns loudly to stderr at boot and every stale-poll tick and records ~/.agentplug/plugins/<name>.local-dev-sideload.json so the state is queryable rather than indistinguishable from a released build. METHOD LESSON: two in-repo docs disagreeing is settled by reading the shipped source, never by trusting the more confident phrasing -- and the losing doc gets corrected the same turn, plus any memo carrying the wrong version pruned, or the stale claim silently outlives the fix.
