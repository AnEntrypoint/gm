Cordis paper (A Programming Paradigm for Spatiotemporal Composability) maps onto gm's plugin/discipline architecture as: (1) revertible effects -> agentplug-runner's plugin load/self-update should pair each load with a composed inverse closure (undo host-import bindings, kv-namespace touches, spool-verb registrations), so a failed/reverted swap recovers pre-load state exactly instead of the current restart-based recovery; (2) reactive coeffects -> disciplines and sibling wasm plugins (bert/libsql/treesitter) should declare an explicit dependency spec (what they require) and provision (what they supply), so config_repo_unreachable/plugin-load-failure deactivates only the dependents whose coeffect is unsatisfied instead of an all-or-nothing fallback; (3) the component/fiber calculus's Inactive/Reloading/Active/Unloading inertial lifecycle maps onto rs-plugkit's non-linear phase graph (SPECIFY..COMPLETE with 12 feedback edges) -- a feedback-edge re-entry (e.g. DECIDE->SPECIFY) is structurally an inertial divert, with mutables.yml rows as the accumulator. Use this mapping to scope future plugkit/agentplug design work toward exact-recoverable, reactively-composed plugin lifecycle rather than restart-based recovery.
