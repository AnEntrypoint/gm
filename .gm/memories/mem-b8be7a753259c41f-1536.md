gm SKILL.md historical playwriter-wrapper-bugs sweep (resolved 2026-07-15, gm commits 27b3009/d6f696a/0ce18ef): four real bugs in the browser verb handler caused prior stub-response/stale-session/truncation/no-debug-capture symptoms. (1) spawnSync shell:true on Windows routed through cmd.exe, which treats &|<>^ as command separators even inside double-quoted args, silently truncating any script/URL containing & (e.g. a real ?a=1&b=2 query string) -- fixed by spawning bun.exe directly with shell:false. (2) bun x <pkg> -e <script> panics on Windows with a known oven-sh/bun fixed-buffer-size index-out-of-bounds bug once combined argv gets long enough -- fixed by writing the script to a temp file and using playwriter's -f flag instead of inlining via -e. (3) playwriter's executor.js truncates displayed stdout at a fixed 10000 chars, silently eating the __GM_RESULT__ sentinel line on any dispatch whose combined output exceeded that cap -- fixed by having the executed script write its result to a dedicated temp file via sandboxed require('fs') scoped to os.tmpdir(), read directly by the wrapper, bypassing playwriter's stdout formatting entirely. (4) page.evaluateOnNewDocument is a Puppeteer method name; playwriter's page is a real Playwright Page, whose equivalent is page.addInitScript -- the wrong name meant window.__gmErrors (and later GL instrumentation) never installed on any dispatch, silently swallowed by an enclosing try/catch; also had to await the addInitScript call itself since it races page.goto otherwise.
