rs-plugkit BrowserWitnessConfig (ragconfig.rs) gate false-negative hazard: the browser-witness-coverage gate only demands a witness for files BrowserWitnessConfig's classifier claims as browser-running. A project whose client code lives outside the hardcoded browser_dir_prefixes list (public/, site/, app/, pages/, components/, client/, web/, src/frontend/, packages/web-app/, frontend/, webapp/) gets every client edit classified as non-browser, so the gate then reports PASS with zero real coverage -- a silent false-negative that is worse than a loud failure. Same class of hazard for any config-driven gate: a classifier that under-recognizes its target silently degrades the guarantee instead of failing loud. Generalizable lesson: when a gate's coverage depends on a pattern-matched classifier, audit whether an unmatched input reads as pass-with-nothing-checked rather than fail-loud.
