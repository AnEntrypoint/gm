Rust crates behind gm

rs-plugkit, rs-search, rs-codeinsight and the agentplug native host
tl;dr
gm is a skill and MCP server for coding agents. It refuses to let the agent mark a task finished until its checks pass. This page lists the four Rust repositories behind it and what each one owns. Read it if you are installing gm, checking what runs on your machine, or changing one of its crates.

Install and check

To install gm, follow the distribution page. The installer places the runner at ~/.gm-tools/agentplug-runner (on Windows, ~/.gm-tools/agentplug-runner.exe), under the plain name, while the release asset carries a platform suffix such as agentplug-runner-linux-x64. Run ~/.gm-tools/agentplug-runner --build-info to see the runner build. Then read a crate's section below for what it owns, and open its repository.

The crates

rs-plugkit

the orchestrator AnEntrypoint/rs-plugkit

Job: owns the state machine, the gates, the orchestrator verbs (instruction, transition, prd-*, mutable-*) and the host verbs (fs_*, exec_js, fetch, the git verbs, and memory). Its one crate is plugkit-core. Its release build targets wasm32-wasip1 and publishes the guest as plugkit-slim.wasm.

It enforces a workflow graph of 146 states (129 principle, 8 tension, 6 gate and 3 terminal), joined by 376 edges. The graph holds 26 gate predicates. Two are marked advisory: true, and the other 24 are not. The lean copy embedded in the orchestrator has the same counts as gm-config/fsm/graph.json.

rs-search

the search fusion library AnEntrypoint/rs-search

Job: a dependency-free Rust library with two modules. fusion fuses ranked lists with Reciprocal Rank Fusion, and tokenize splits text into identifier-aware tokens. It has no BM25 and no vector code. rs-plugkit runs the BM25 and embedding channels of codesearch and calls this library to fuse their ranked lists and tokenize queries. It has no CLI and no server.

rs-codeinsight

the code structure parser AnEntrypoint/rs-codeinsight

Job: a standalone tree-sitter analyzer of code structure, built as a CLI and a library. The call-graph verbs callers and impact run natively in rs-plugkit, not by linking this crate.

agentplug

the native host AnEntrypoint/agentplug

Job: agentplug-runner is the native host that loads plugkit-slim.wasm and serves the spool, the directory of request and response files that gm writes and polls. Its commands include spool, daemon, dispatch, takeover and plugin. One daemon runs per install directory and serves each project registered with it, and the cwd of a call is resolved to its project root. Its crates are agentplug-host, agentplug-runner, and the browser crates agentplug-lightpanda and agentplug-lightpanda-wasm.

How a change ships

A change to skills/ pushed to main publishes a GitHub Release of the gm repository through skill-release.yml. The release is tagged v<version> and holds the archive gm-skill-<version>.tar.gz, which contains the skills/ tree, and its .sha256 file. install.sh checks that file before it unpacks the archive. In rs-plugkit, release.yml calls the reusable workflow wasm-plugin-release.yml, which publishes the WASM guest.

Retired

rs-exec and rs-learn are retired. Their repositories are archived, and each one's README points at rs-plugkit or gm.
