Rust crates behind gm

rs-plugkit, rs-search, rs-codeinsight and the agentplug native host
tl;dr
gm ships one WebAssembly guest, plugkit-slim.wasm, built from rs-plugkit for wasm32-wasip1. The native agentplug-runner loads it and serves the spool. rs-search backs the codesearch verb, and rs-codeinsight is a standalone tree-sitter analyzer. The repositories rs-exec and rs-learn are retired.

What you can do next

Check the runner you have with agentplug-runner --build-info, as described on the distribution page. Read a crate's section below for what it owns, then open its repository.

The crates

rs-plugkit

the orchestrator AnEntrypoint/rs-plugkit

Job: owns the state machine, the gates, the orchestrator verbs (instruction, transition, prd-*, mutable-*) and the host verbs (fs_*, exec_js, fetch, the git verbs, and memory). Its one crate is plugkit-core, which builds to plugkit-slim.wasm for wasm32-wasip1.

The walk it enforces is a lean graph embedded in its orchestrator, which matches the counts of gm-config/fsm/graph.json: 146 nodes (129 principles, 8 tensions, 7 gates and 2 terminal nodes), 376 edges, and 26 gates. 24 of the gates block a move, and 2 are advisory.

rs-search

the file finder AnEntrypoint/rs-search

Job: provides the rank fusion that codesearch uses to combine its BM25 and embedding results. The BM25 and embedding channels run in rs-plugkit.

rs-codeinsight

the code structure parser AnEntrypoint/rs-codeinsight

Job: a standalone tree-sitter analyzer of code structure, built as a CLI and a library. The call-graph verbs callers and impact run natively in rs-plugkit, not by linking this crate.

agentplug

the native host AnEntrypoint/agentplug

Job: agentplug-runner is the native host that loads plugkit-slim.wasm. Its commands are spool, daemon, dispatch, takeover and --build-info. One shared daemon serves the spool for every project on the machine. Its crates are agentplug-host, agentplug-runner, and the browser crates agentplug-lightpanda and agentplug-lightpanda-wasm.

How a change ships

A skill change pushed to main publishes a gm-skill GitHub Release through skill-release.yml. The release archive holds the skills/ tree and a SHA-256 file, and the installers check that file before they install. The WASM guest publishes through the release workflow of rs-plugkit.

Retired

rs-exec and rs-learn are retired. Their repositories are archived, and each one's README points at rs-plugkit or gm.
