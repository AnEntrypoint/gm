# Script and CI rationale

Moved out of AGENTS.md to keep it under 30,000 bytes. Owner: the repo root. Each entry names the script or workflow it explains.


- `scripts/triage/check-pins.sh`: an unpublished pin breaks every fresh recursive clone, so it fetches the pinned sha into a throwaway bare repo.
- `scripts/remote-cmp.mjs`: raw paths once produced `/contents/C:/...` 404s that read as "absent"; 401 and 403 are auth or rate limit, never absence.
- `scripts/build-graph-page.mjs`: page numbers come from the graph JSON; a broken edge refuses the page before any file is written.
- `scripts/sweep-config-sync-litter.mjs`: deleting orphaned state is a cache miss, not data loss; `--max-age-days` is opt-in.
- `gm-mcp/.github/workflows/verify.yml` (workflow name `build-verify`): its name must keep "build". `bump-pins` holds the submodule pin while a release, publish, build or wasm run is non-green, so renaming the workflow silently releases the hold.
- `.github/workflows/house-clean.yml` keeps only the latest release per `-bin` repo; the installers read only that, so superseded releases have no reader.
- gm-mcp bundle drift: a running gm-mcp snapshots the bundle it booted from, and reloads only to a provably newer bundle. Handover passes the listening socket over IPC so the port is never closed.
- Reaper: child-ledger attribution is its safety gate. A process is retired only when every predicate measured true (null means unknown). Browser leases retire only on positive evidence of death, not heartbeat. The runner, http server and supervisor are detached on purpose, so they are never candidates.
- `gm-mcp/src/ports.js`: probes answer null when unmeasured, never false. Only "nothing listening" licenses retiring a port.
- Tool aliases (`rs-plugkit/crates/plugkit-core/src/wasm_dispatch/verbs/git.rs`): `git_reset` takes `ref` or `rev`, and `mode` or `hard`, each pair refused together as `conflicting_fields`; `git_revert` takes `paths` or `ref`. Boolean fields in `gm-mcp/src/verb-table.js` use `booleanLike` (boolean or string), not strict `z.boolean()`.
- Install bundle host: an unreachable bundle host warns and keeps the deployed bundle (`install.sh`, `bin/gm-install.js`); it never aborts an install that already has one.
- `scripts/sweep-config-sync-litter.mjs`: usage `node scripts/sweep-config-sync-litter.mjs [--root <dir>]... [--temp] [--max-age-days N] [--apply]`. By default only orphaned state (checkout gone) is swept; `--max-age-days N` also sweeps older state while its checkout survives, a cache miss that costs the next sync its debounce and backoff. Without `--apply` it only reports; exit 0 always, a sweep is never a gate. Deleting one is a cache miss, not data loss: the "already at tip" test reads `git rev-parse HEAD` in the checkout, never the stored sha. It never touches the checkout dir, the `.lock` directory (single-flight mutex), `.staging*` or `.retired`. Nothing in rs-plugkit deletes this state: `config_sync.rs` removes only `.tmp` files.
- `scripts/check-doc-counts.mjs`: usage `check-doc-counts.mjs [root]`. Every count claim in the site and docs must equal a count of the state machine (`gm-config/fsm/graph.json`), the hop graph (`skills/dream-rsi/gm-graph.json`). Exit 1 on a claim that matches none; prints RESULT: PASS otherwise.
- `scripts/check-doc-paths.mjs`: usage `check-doc-paths.mjs [root]`. Every repository path the site and docs name must resolve on disk; exit 1 on a missing one. A bare file name (specify.md, state.md) is not checked: it names a served stage, runtime file or prose key. Paths under an uninitialised submodule are counted as skipped.
- `scripts/check-graph-traversal.mjs`: usage `check-graph-traversal.mjs [root]`. Checks that every node is reachable and no non-terminal node is a dead end in either graph, that the state machine's terminal is reachable with a COMPLETE edge to it, that the hop convergence terminal and halt nodes are terminal, and that shared nodes agree on kind. Exit 1 on failure.
- `scripts/sync-prose.mjs`: `skills/gm/prose` is the source; `gm-config/prose` is generated. Edit the skill, then run the script.
- `scripts/triage/doctor.sh`: usage `doctor.sh` (run from the gm root). Exit 1 if the watcher is dead or a pin is unpublished. A repo is RED only when the newest run of a workflow on main failed; an older failure that a later run fixed is not reported.
- `scripts/triage/runner-status.sh`: `.status.json` is written by one process and can outlive it. A daemon serving dispatches while the status pid is gone leaves a stale status file; a response written in the last 5 minutes proves a live runner, so it is not a dead watcher and a second one must not start.
- `notify-gm.yml` in each submodule's `.github/workflows/` (present in every submodule; first in gm-config): on push to main it sends `submodule-released` to AnEntrypoint/gm with `PUBLISHER_TOKEN`, so bump-pins runs within seconds instead of at the next cron tick. It exits 1 when the token is unset, so a missing secret shows as a red run.
- `gm-config/scripts/witness-parallel-slots-decline.mjs`: witnesses that the "Parallel slots (standing rules)" section of `prose/entry.md` carries the declined-successor obligation. Usage: `[path-to-entry.md]`.
- `gm-config/scripts/witness-refill-trigger.mjs`: witnesses that the section names the host completion notice as the refill trigger, records the measured wait-fallback distribution, and that the instructions code emits a launch list rather than a count. Usage: `[path-to-entry.md] [path-to-instructions-mod.rs]`.
