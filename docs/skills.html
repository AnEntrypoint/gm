The gm skills

one entry skill, four walk skills, six discipline skills
tl;dr
gm is the entry skill, skills/gm/SKILL.md, installed as /gm. It holds standing rules and points the agent at the walk skills. The prose for the current node and the live graph state come from the orchestrator through the instruction verb, not from the entry skill. The release ships eleven skill directories that each contain a SKILL.md: gm, four walk skills and six discipline skills.

What you can do next

Install the skills with install.sh, install.ps1 or node bin/gm-install.js, as described on the distribution page. Then open a project and dispatch instruction to read the current node's prose and the state it sits in.

The entry skill

skills/gm/SKILL.md is the only skill an agent loads up front. It sets the autonomy rules and the search and git routing (code search goes through codesearch, git goes through the git verbs). The walk loop belongs to gm-orchestrate. Each node's prose is served by instruction when the agent asks for it.

The walk skills

These four skills sit beside gm. Each one is loaded by name once a walk starts.

gm-orchestrate

main-thread pool loop
doesTicks the subagent pool: it launches plan rows and graph hops, waits on them, and refills freed slots. It owns the pool terms ceiling, live, floor and shortfall, the walk loop and its exit check.

gm-hop

one traversal hop
doesApplies one principle from the graph to one surface and writes one receipt. It names the next principle to visit.

gm-prd

one plan row, one run
doesCloses one plan row through nine stages in one run. Invoked with row=<id>; session=<SESSION_ID>.

gm-continue

terminal handoff
doesRuns when the walk reaches COMPLETE with no pending plan rows. It searches for remaining work before the walk ends.

The discipline skills

Six skills hold method rather than walk control. Each one is loaded by name when its method fits the task.

SkillUse

polaris-goal-compilerCompiles a goal into gated task atoms and claim ceilings.

dream-rsiProposes strategy changes from observation logs and measures gm-graph coverage. It proposes only and never deploys.

The orchestrator verbs

An agent dispatches a verb by writing a request file to .gm/exec-spool/in/<verb>/<N>.txt. The runner reads the file and writes the reply to .gm/exec-spool/out/, named after the verb and the request id.

VerbDoes
instructionReturns the prose for the current node with the live graph state, the plan summary and the open mutables.
transitionAsks the orchestrator to move to a target node. It accepts the move when the gates on that edge pass, or it refuses and names the failed gate.
prd-add, prd-resolve, prd-listAdd a plan row, close a row with recorded witness_evidence, and list rows in .gm/prd.yml.
mutable-add, mutable-resolve, mutable-listRecord an open question, close it once a live check answers it, and list the open questions.
fsm-vendorCopies the graph and the prose into the project so that the project can override them.
codesearch, grepcodesearch is ranked search over the project. grep is an exhaustive literal or regex scan that reports each hit as path:line.
recall, memorizeSearch the project's memory by meaning, and store a memory.
exec_jsRuns code in a subprocess. A leading timeoutMs=<ms> line sets its budget, with a default of 300000 ms.
git_finalize, git_push, git_show, ci-statusCommit and push, show a commit, and check CI for a commit.
healthReports the runner state, watcher liveness and recent errors.
gm_resultReads a reply that is cut at the reply size limit, from its spill file.

How the skills install

Install from a checkout and each skill directory is linked, not copied. The installers run beside skills/ or with GM_SKILL_SOURCE_DIR set. They create a directory junction on Windows and a symlink elsewhere, so ~/.claude/skills/<name>/SKILL.md and <checkout>/skills/<name>/SKILL.md are one file, and a source edit is served on the next dispatch. With no local source, the installers copy the release archive. The release ships every skill directory, so one install places all of them.
