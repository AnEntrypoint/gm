The gm skills

what the gm skills are, and which verbs serve them
tl;dr
gm is a workflow for AI coding agents. It drives an agent through engineering work in a git project: code search, git verbs, recorded memory, and a plan whose rows each close only with recorded evidence. It is for developers who run coding agents such as Claude Code, Cursor, Codex or Gemini. The release ships eleven skills, each a directory under skills/ with a SKILL.md: the /gm entry skill, four walk skills and six discipline skills. Install it from the distribution page. The install also registers the gm MCP server, which serves the verbs. Then type /gm in your coding agent to load the skill.

After you load /gm

Once /gm is loaded, the agent dispatches verbs. instruction reads the prose for the current phase, and phase-status gives a state check. The verb list below names the verbs this page documents. The verb inventory gives each verb's body shape.

Terms

  • /gm: the entry skill, read from skills/gm/SKILL.md. It is the skill, not the MCP server.
  • gm MCP server: the server that serves the verbs. An agent calls it through its gm_codemode tool.
  • walk: one run of the gm state machine that the agent drives to completion on its main thread, through the gm-orchestrate skill.
  • plan row, also called a PRD row: one entry in the plan. An open row is one file in .gm/prd/. It closes only with recorded witness_evidence.
  • hop: one traversal of a graph node, performed by one gm-hop subagent.
  • gate: a graph node that checks a condition before the walk moves on. A refused move is a gate denial. The denial names the verb to dispatch next.
  • mutable: an open question that the agent records with mutable-add instead of asking the user.
  • verb: a named gm operation an agent calls, such as codesearch or instruction.
  • dispatch: one request an agent sends to run a verb.

The entry skill

skills/gm/SKILL.md is the entry skill for engineering work. Its Autonomy section sets how far the agent acts without asking, and its routing covers search and git: code search goes through codesearch, and git goes through the git verbs.

The walk skills

These skills run inside a walk. gm-orchestrate and gm-hop are invoked only from gm and are not loaded directly.

gm-orchestrate

runs the walk loop
doesRuns the pool loop of a walk, which keeps the pool full. The pool is the set of parallel subagents a walk runs at once. The loop observes, launches plan rows and graph hops, logs, waits, refills freed slots and exits.

gm-hop

one step through the graph
doesApplies one principle from the graph to one surface and writes one receipt. It names the next principle to visit.

gm-prd

closes one plan row
doesCloses one plan row through nine stages in one run.

gm-continue

final check when the walk is done
doesRuns when the walk reaches its final phase, COMPLETE, with no pending plan rows. It searches for remaining work before the walk ends.

These skills hold method rather than walk control. Each one is loaded when its frontmatter description matches the task.

How the skills are installed

From a checkout, install.sh, install.ps1 and bin/gm-install.js link each skills/<name> into ~/.claude/skills/<name> and ~/.agents/skills/<name>: a symlink on macOS and Linux, a junction on Windows. A source edit is served on the next dispatch. With no durable source, such as the release tarball or an npx cache, the installer copies the skill, announces the copy, and records the mode in <root>/.gm-skill-install-modes.

An install that must be replaced is parked under the dotted <root>/.gm-skill-prelink/ directory and is never deleted. Deleting it needs --force-link in bin/gm-install.js, or GM_SKILL_LINK_FORCE=1 in install.sh and install.ps1. On MINGW, MSYS and Cygwin only a junction counts as a link.

The verbs this page documents

An agent dispatches a verb through the gm_codemode tool of the gm MCP server, as gm.<verb>({...}) in the code body. Without MCP, it writes the request to .gm/exec-spool/in/<verb>/<SESSION_ID>-<N>.txt and reads the reply from .gm/exec-spool/out/<verb>-<SESSION_ID>-<N>.json, where <N> is <pid>-<ms>-<counter>.

phase-statusReturns the compact state only: the phase, prd_pending_count and the pending mutables, with no prose.
transitionMoves the walk to a target node, when the gates on that move allow it.
prd-add, prd-resolve, prd-listAdds, resolves and lists plan rows. Each open row is one file in .gm/prd/ in the project. A resolved row moves to .gm/prd-log.jsonl.

codesearch, grepcodesearch is ranked search over the project by default. Its literal and regex modes are exhaustive. grep is an exhaustive literal or regex scan that reports each hit as path:line.
