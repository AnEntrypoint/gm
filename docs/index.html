1. Install

Linux, macOS and Windows, x64 or arm64. On Linux and macOS, one command, once per machine. It downloads the latest release, checks its sha256 and size, unpacks into ~/.gmnew/current, then runs the installed binary's gm install subcommand, which registers gm for Claude Code at user level.

curl -fsSL https://raw.githubusercontent.com/AnEntrypoint/gm/main/scripts/install.sh | sh

Needs curl, tar, and sha256sum or shasum. Node is not needed to run gm.

The archive holds gm and gm-core (gm.exe and gm-core.exe on Windows) and the leaves, skills and defaults directories. Both installers check the two binaries, retry downloads, and write .gmnew-update.json when it is missing.

To register gm with a playwriter config:

curl -fsSL https://raw.githubusercontent.com/AnEntrypoint/gm/main/scripts/install.sh | sh -s -- --mcp-config <path>

Windows x64 and arm64 build and test in CI and are published as .zip. Run scripts/install.ps1 with PowerShell; it unpacks into %USERPROFILE%\.gmnew\current and runs gm.exe install. Its -McpConfig argument forwards the config to gm.exe install.

2. Connect Claude Code

The installer runs ~/.gmnew/current/gm install (on Windows, %USERPROFILE%\.gmnew\current\gm.exe install). The binary writes mcpServers.gm in ~/.claude.json (on Windows, %USERPROFILE%\.claude.json) at user scope, with command set to its own path and args starting with serve. Every other key is kept; running it again replaces the gm entry.

~/.gmnew/current/gm install [--mcp-config <path>]

With --mcp-config <path>, those two arguments are appended to args. With GMNEW_SKIP_REGISTER=1, the installer leaves the files in place and skips this step; run the command above later to register.

Check mcpServers.gm in ~/.claude.json for the command path. Remove the same key to disconnect. A project .mcp.json with its own gm entry overrides this one in that project. Keep such a file out of the gm checkout.

3. Use it

Start a Claude Code session in a project. The session calls gm's three tools, and gm works in the session's folder unless told otherwise. Every run writes an append-only log under runs/ in the workspace.

  1. The model calls next_context at the start of each step. The reply carries the rules, the task, and the events since the last step.
  2. The model does the work in one run_code call. Its body is JavaScript with a gm object whose methods are the verbs.
  3. The model calls finish with a witness: one string quoting the output it actually saw. A finish without a witness is refused.

4. The three tools

ToolPurpose
next_contextBegin a step. Returns the rules, the task, the pending events, and the step count.
run_codeRun a JavaScript body against the project. Verbs are functions on gm.
finishEnd the run. Needs a witness. Refused while a background run or an open row remains.

The server serves these three tools.

5. run_code and its verbs

Each verb is a function on gm, awaited with one object argument:

const [a, b] = await Promise.all([
  gm.read_file({ path: 'a.txt' }),
  gm.read_file({ path: 'b.txt' }),
]);
return { a: a.output.length, b: b.output.length };

A failed verb returns { ok: false, error } and does not stop the body. Wrap a risky step in gm.try to isolate it.

Files and shell

read_file, write_file, edit_file, stat_file, list_dir, run_shell.

Search

search (BM25 over tracked files), grep, wiki_search, wiki_write, callers, impact.

Jobs

job_start, job_status, job_stop. A body that runs past its budget (180 seconds by default, at most 300000) becomes a background run; job_status with waitMs waits for it.

Git

git_status, git_add, git_rm, git_commit, git_push, git_log, git_diff, git_show, git_fetch, git_pull, git_checkout, git_branch, ci_status.

Rows and review

prd_add, prd_list, prd_park, prd_reopen, prd_resolve, prd_delete, unknown_add, unknown_list, unknown_resolve, review_packet, review_record, review_join.

Network and logs

fetch, query_log (reads the run's own log), and any MCP server configured for the project as gm.<server>_<tool>.

Call gm.verbs() inside run_code to get each verb's schema as data. Wrap a call that may throw in gm.try(fn) so one failure does not hide the rest of a batch; both helpers are named in run_code's description.

Workflow graphs

Work that splits into independent units is shaped by skill://gm/WORKFLOWS.md, a served skill file read on demand with gm.read_file({ path: 'skill://gm/WORKFLOWS.md' }). It holds the work order (search and insight, just-in-time execution, elimination waves, validation by running code), the graph shapes (scout then fan out, pipeline over barrier, adversarial refuters, loop until dry, a completeness critic, no silent caps, a budget guard), the map to gm verbs, and the witness counts. The seven rules and the connect-time instructions stay short; a single-file edit stays in one body. Re-read it after a compaction before the next fan-out. When stepsLeft reaches 0, call finish with a witness and then next_context to open a successor run; do not call next_context first.

6. Updates

The server checks the latest release when it starts and then every 15 minutes. Each check is a conditional request, so an unchanged release costs one small response. It downloads a build only when that target's archive has changed, and only one check runs at a time across processes. Each build is published under its own file names, the manifest is uploaded last, and the last three builds stay on the release.

A development build never updates itself. Set GMNEW_AUTO_UPDATE=0 to turn updates off.

To check now:

~/.gmnew/current/gm update

7. Commands

CommandWhat it does
gm serveServe the MCP tools on stdio. This is what Claude Code runs.
gm installWrite the user-scope Claude Code entry; --mcp-config adds its two arguments to serve.
gm workerRun one worker directly. Used by the supervisor.
gm doctorCheck the install’s runtime.
gm updateCheck for a newer release and install it if one exists.

8. Environment

VariableEffect
GMNEW_AUTO_UPDATE=0Turn off the background update check.
GMNEW_UPDATE_URLRead the manifest from this URL instead of the default release.
GMNEW_RELEASE_BASEInstaller only: the release directory to download from.
GMNEW_SKIP_REGISTER=1Installer only: unpack the files and skip the gm install registration.

9. Troubleshooting

sha256 mismatch while installing

The manifest and archive disagree. Run the install again. Each archive is versioned as gmnew-<version>-<target>.tar.gz on Linux and macOS or .zip on Windows, so a mismatch should no longer occur on a fresh release.

"another update is running"

An update lock is held. The lock records its owner's process id. If that process has exited, the next check takes the lock over. Otherwise wait for the running check to finish.

gm does not connect

Check mcpServers.gm in ~/.claude.json (on Windows, %USERPROFILE%\.claude.json): command should name the installed gm and args should start with serve. Run the installed gm install again to replace a stale path, then gm doctor. If a project .mcp.json defines its own gm entry, that entry is the one Claude Code uses in that project.

Windows

Windows x64 and arm64 build and test jobs pass in CI and are published as .zip. Use scripts/install.ps1; -McpConfig forwards a worker config.

10. Uninstall

Delete mcpServers.gm from ~/.claude.json (on Windows, %USERPROFILE%\.claude.json), then remove the install:

rm -rf ~/.gmnew

On Windows, remove %USERPROFILE%\.gmnew instead.
