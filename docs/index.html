1. Install

Linux and macOS, x64 or arm64. One command, once per machine. It downloads the latest release, checks its sha256 and size, unpacks into ~/.gmnew/current, and registers gm for Claude Code at user level.

curl -fsSL https://raw.githubusercontent.com/AnEntrypoint/gm/main/scripts/install.sh | sh

Needs curl, tar, and sha256sum or shasum. Node is not needed to run gm.

To register gm with a playwriter config:

curl -fsSL https://raw.githubusercontent.com/AnEntrypoint/gm/main/scripts/install.sh | sh -s -- --mcp-config <path>

Windows is not published yet. The Windows build fails most of its tests, so the release carries Linux and macOS only.

2. Connect Claude Code

The installer runs add-mcp, pinned to 2.6.1, which writes a user-scope entry named gm:

npx -y add-mcp@2.6.1 <path-to-gmnew> --args serve -n gm -g -a claude-code -y

add-mcp takes the executable as its target and each argument after --args. Do not pass the whole command as one string: add-mcp then stores it as the executable name, and the server cannot start.

Check the entry:

npx -y add-mcp@2.6.1 list -g

Remove it:

npx -y add-mcp@2.6.1 remove gm -g -y

A project .mcp.json with its own gm entry overrides this one in that project. Keep such a file out of gmc.

3. Use it

Start a Claude Code session in a project. The session calls gm's three tools, and gm works in the session's folder unless told otherwise. Every run writes an append-only log under runs/ in the workspace.

  1. The model calls next_context at the start of each step. The reply carries the rules, the task, and the events since the last step.
  2. The model does the work in one run_code call. Its body is JavaScript with a gm object whose methods are the verbs.
  3. The model calls finish with a witness: one string quoting the output it actually saw. A finish without a witness is refused.

4. The three tools

ToolPurpose
next_contextBegin a step. Returns the rules, the task, the pending events, and the step count.
run_codeRun a JavaScript body against the project. Verbs are functions on gm.
finishEnd the run. Needs a witness. Refused while a background run or an open row remains.

The server serves these three tools.

5. run_code and its verbs

Each verb is a function on gm, awaited with one object argument:

const [a, b] = await Promise.all([
  gm.read_file({ path: 'a.txt' }),
  gm.read_file({ path: 'b.txt' }),
]);
return { a: a.output.length, b: b.output.length };

A failed verb returns { ok: false, error } and does not stop the body. Wrap a risky step in gm.try to isolate it.

Files and shell

read_file, write_file, edit_file, stat_file, list_dir, run_shell.

Search

search (BM25 over tracked files), grep, wiki_search, wiki_write, callers, impact.

Jobs

job_start, job_status, job_stop. A body that runs past its budget (180 seconds by default, at most 300000) becomes a background run; job_status with waitMs waits for it.

Git

git_status, git_add, git_rm, git_commit, git_push, git_log, git_diff, git_show, git_fetch, git_pull, git_checkout, git_branch, ci_status.

Rows and review

prd_add, prd_list, prd_resolve, prd_delete, unknown_add, unknown_list, unknown_resolve, review_packet, review_record, review_join.

Network and logs

fetch, query_log (reads the run's own log), and any MCP server configured for the project as gm.<server>_<tool>.

Call gm.verbs() inside run_code to get each verb's schema as data.

6. Updates

The server checks the latest release when it starts and then every six hours. It downloads a build only when the release has changed, and only one check runs at a time across processes. Each build is published under its own file names, the manifest is uploaded last, and the last three builds stay on the release.

A development build never updates itself. Set GMNEW_AUTO_UPDATE=0 to turn updates off.

To check now:

~/.gmnew/current/gmnew update

7. Commands

CommandWhat it does
gmnew serveServe the MCP tools on stdio. This is what Claude Code runs.
gmnew workerRun one worker directly. Used by the supervisor.
gmnew doctorCheck the install’s runtime.
gmnew updateCheck for a newer release and install it if one exists.

8. Environment

VariableEffect
GMNEW_AUTO_UPDATE=0Turn off the background update check.
GMNEW_UPDATE_URLRead the manifest from this URL instead of the default release.
GMNEW_RELEASE_BASEInstaller only: the release directory to download from.
GMNEW_SKIP_REGISTER=1Installer only: install the files, skip the add-mcp registration.

9. Troubleshooting

sha256 mismatch while installing

The manifest and archive disagree. Run the install again. Each build has its own file names, so a mismatch should no longer occur on a fresh release.

"another update is running"

An update lock is held. The lock records its owner's process id. If that process has exited, the next check takes the lock over. Otherwise wait for the running check to finish.

gm does not connect

Run npx -y add-mcp@2.6.1 list -g and check the command path. Then run ~/.gmnew/current/gmnew doctor. If a project .mcp.json defines its own gm entry, that entry is the one Claude Code uses in that project.

Windows

Not published yet.

10. Uninstall

npx -y add-mcp@2.6.1 remove gm -g -y
rm -rf ~/.gmnew
