How gm is installed
and checked

AnEntrypoint
Summary
gm installs its skills, the native agentplug-runner and a local Model Context Protocol (MCP) server bundle. The installers check SHA-256 checksums for the skill archive and the runner. The agent drives the walk through the spool that the installed runner serves.

What you can do next

Run one installer below, then check the installed runner with --build-info (section 4). Register the MCP server with the repair command in section 3 if your agent host does not list the gm tool.

1. Install

On macOS or Linux:

curl -fsSL https://raw.githubusercontent.com/AnEntrypoint/gm/main/install.sh | sh

In Windows PowerShell:

irm https://raw.githubusercontent.com/AnEntrypoint/gm/main/install.ps1 | iex

The scripts download the release archive and the runner. Each download is checked against its published SHA-256 file. The scripts also download the gm-mcp server bundle. If that download fails, the installer warns, and the spool protocol still works without the bundle.

To install the skills and register the MCP server in every detected agent host, use one command:

npx github:AnEntrypoint/gm -g

Drop -g to install into the current project only. The Node.js installer bin/gm-install.js also takes --mcp-only, which repairs an MCP registration without reinstalling anything, and --skills-only, which installs only the skills.

2. Run a verb from a shell

A verb does not need an agent host. In a checkout, ./bin/gm forwards to the same dispatch that the gm MCP tool runs, so a plain shell reaches the project spool with no MCP client in the loop.

./bin/gm codesearch literal BUNDLE_VERSION --path gm-mcp/src

3. Connect the MCP server

The installed bundle is ~/.gm-tools/gm-mcp-server.mjs. Agent hosts launch it with Node.js from that local file. A registration never launches the server from an npx GitHub spec, because that path re-resolves the package on every connect and can exceed the host's connect timeout.

To repair a user registration:

node bin/gm-install.js -g --mcp-only

To repair a project registration:

node bin/gm-install.js --mcp-only

Restart the agent host after a registration change.

The server also serves stateless streamable HTTP on the local machine, at http://127.0.0.1:8787/mcp. In Claude Code, register that transport with:

claude mcp add --transport http gm http://127.0.0.1:8787/mcp -s user

Start the shared HTTP server, or confirm that one is listening, with:

node ~/.gm-tools/gm-mcp-server.mjs ensure-http

ensure-http starts the server when no listener exists. http-supervise is the subcommand that supervises the server.

A reply longer than 24,000 characters is cut. The rest goes to a spill file under .gm/exec-spool/out/, and gm_result reads that file.

4. Inspect the installed runner

On macOS or Linux, print the runner's build identity:

~/.gm-tools/agentplug-runner --build-info

In Windows PowerShell:

& "$env:USERPROFILE\.gm-tools\agentplug-runner.exe" --build-info

The output names the compiled commit and whether the build is a release build. Build identity checks compare the commit and release_build fields that --build-info reports, never the version string, because a release with the same version number can be a downgrade. The installers verify each download against its .sha256 file.

The runner serves the project spool. Its status file is .gm/exec-spool/.status.json. A fresh heartbeat does not prove that the runner process exists. Start the spool host with:

~/.gm-tools/agentplug-runner spool

5. Source ownership

The root .gitmodules file lists 11 submodules. Clone them when you develop one of these dependencies:

git clone --recurse-submodules https://github.com/AnEntrypoint/gm.git

For an existing checkout:

git submodule update --init --recursive
SourceResponsibility
skills/gm/SKILL.mdAgent workflow and tool routing.
gm-config/Default prose, gate text, messages and the workflow graph (fsm/graph.json).
rs-plugkit/The gm WASM guest: orchestration, memory and code search.
agentplug/The native agentplug-runner host.
gm-mcp/The MCP wrapper around spool request and response handling.
agentplug-bert/, agentplug-libsql/, agentplug-treesitter/Shared embedding, database and syntax plugins.
rs-codeinsight/, rs-search/Code structure analysis and the code search backend.
agentplug-crux/Plugin source.
vendor/tencentdb-agent-memory/The vendored TencentDB-compatible memory system.

Durable memory documents live under .gm/memories/. The root README.md and AGENTS.md hold the source and runtime contracts.

6. Release evidence

The skill-release.yml workflow runs on a push to main that changes skills/**. It bumps the version in gm.json and package.json, packages the skills into gm-skill-<version>.tar.gz, and publishes the archive with its SHA-256 file to a tagged GitHub Release.

The runner publishes from agentplug to the AnEntrypoint/agentplug-bin releases. A commit or a push does not prove that a release exists. Check the workflow run and fetch the expected artifact before you treat a release as published.

A change to the MCP wrapper requires rebuilding its committed bundle. A change to a dependency requires updating its pin in the root submodule.
