The SQLite Model:
One Skill, One Wasm, Open All The Way Down

AnEntrypoint
May 2026
Thesis
gm installs skills, a native WebAssembly host, and a local Model Context Protocol server from public source. The scripts check release checksums for the skill archive and runner. The agent drives the workflow through the installed server or project spool.

1. Install gm

The gm-skill release contains the skills. The installers also download the native agentplug-runner host and the local Model Context Protocol (MCP) server bundle. Users do not need a Rust build toolchain.

On macOS or Linux:

curl -fsSL https://raw.githubusercontent.com/AnEntrypoint/gm/main/install.sh | sh

In Windows PowerShell:

irm https://raw.githubusercontent.com/AnEntrypoint/gm/main/install.ps1 | iex

The scripts check SHA-256 checksums for the skill archive and runner download. They get the MCP bundle from the public gm-mcp repository. The bundle download does not have a release checksum check.

To install the skill and MCP registration in detected agent hosts, use the Node.js installer:

npx github:AnEntrypoint/gm -g

Omit -g for a project installation. The published source defines the supported installer options in bin/gm-install.js.

2. Connect the installed MCP server

The installed bundle is ~/.gm-tools/gm-mcp-server.mjs. Agent hosts launch it with Node.js. A registration uses this local file, so each connection does not reinstall a GitHub package.

To repair a user registration:

npx github:AnEntrypoint/gm -g --mcp-only

To repair a project registration:

npx github:AnEntrypoint/gm --mcp-only

Restart the agent host after a registration change. A running session retains the connection that it opened.

The server also supports a shared HTTP transport on the local machine. In Claude Code, register that transport with:

claude mcp add --transport http gm http://127.0.0.1:8787/mcp -s user

Start the shared HTTP server through the installed bundle:

node ~/.gm-tools/gm-mcp-server.mjs ensure-http

The default transport uses the host's standard input and output pipes. A lost pipe ends that connection. The HTTP transport permits a client to reconnect.

3. Inspect the installed runner

The runner executes WebAssembly (WASM) plugins and serves project spool requests. The agent drives the workflow through those requests. The daemon can serve several projects on one machine.

On macOS or Linux, inspect the runner's build identity:

~/.gm-tools/agentplug-runner --build-info

In Windows PowerShell:

& "$env:USERPROFILE\.gm-tools\agentplug-runner.exe" --build-info

The identity includes the compiled commit and release-build flag. The runner protects a local build from replacement by its automatic release updater. An update refusal can also come from the configured update guard.

Check the reported build identity and update refusal before changing an installation. Keep project state and runtime state available for diagnosis. The project status file is .gm/exec-spool/.status.json.

When the installed runner is absent from the process table, the documented spool entry point starts it. A fresh heartbeat alone does not prove that the process still exists.

On macOS or Linux:

~/.gm-tools/agentplug-runner spool

In Windows PowerShell:

& "$env:USERPROFILE\.gm-tools\agentplug-runner.exe" spool

4. Source ownership

The root .gitmodules file lists the dependency repositories. Clone their source when developing a dependency:

git clone --recurse-submodules https://github.com/AnEntrypoint/gm.git

For an existing checkout:

git submodule update --init --recursive

Code, history, and memory indexes share the project database at .gm/gm.db. Durable memory documents live under .gm/memories/. See README.md and AGENTS.md for the source and runtime contracts.

5. Release evidence

The skill-release.yml workflow runs when a push to main changes skills/**. It increases the package version, packages the skills, and publishes a GitHub Release archive with its SHA-256 file.

The runner has a separate release workflow in agentplug/. Its release assets are published to AnEntrypoint/agentplug-bin. The source workflows define the build targets and update channel.

A commit or push alone does not prove that a release exists. Inspect the workflow result and fetch the expected artifact before treating publication as complete.

Source changes to the MCP wrapper require rebuilding its committed bundle. Changes to a dependency require updating the root submodule pin.
