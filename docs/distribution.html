Install gm and check
that it works

AnEntrypoint
Summary
gm is a state machine for coding agents: a fixed set of states, with gates that decide when work is done. The coding agent drives the state machine, and a walk, one run of the state machine, completes only when the state machine accepts COMPLETE, every required row (one PRD entry) is completed, and gm-continue has checked for remaining work. This page is for developers who run Claude Code, Cursor, Codex or Gemini. The installers place the gm skills, the native agentplug-runner host and a local Model Context Protocol (MCP) server bundle. After install, your coding agent sends gm requests to a local runner.

1. Install

Pick the command for your system. Each one installs the parts it names:

  • Any system, all parts: fetch the MCP server bundle once with curl -fsSL https://raw.githubusercontent.com/AnEntrypoint/gm-mcp/main/bin/gm-mcp-server.js -o ~/.gm-tools/gm-mcp-server.mjs, then register it with claude mcp add gm -s user -- node ~/.gm-tools/gm-mcp-server.mjs. The server installs the skills into ~/.claude/skills and ~/.agents/skills, and the agentplug runner and gm guest from their releases, on its first start. No clone or npx spec is involved.
  • macOS or Linux, runner only: curl -fsSL https://raw.githubusercontent.com/AnEntrypoint/gm/main/install.sh | sh installs the runner into ~/.gm-tools, then runs the runner with no command. The runner prints its usage line and exits with status 1, so that status is expected. Section 4 checks the installed runner.
  • macOS or Linux, skills and MCP server bundle only: curl -fsSL https://raw.githubusercontent.com/AnEntrypoint/gm/main/install.sh | sh -s -- install
  • Windows PowerShell, runner only: irm https://raw.githubusercontent.com/AnEntrypoint/gm/main/install.ps1 | iex installs the runner the same way, then runs the runner with no command. The runner prints its usage line and exits with status 1, so that status is expected.
  • Windows, skills and MCP server bundle only: from a checkout, run powershell -ExecutionPolicy Bypass -File install.ps1 install.

The MCP server bundle (gm-mcp) is downloaded without a checksum, unlike the runner download, which is checked against its .sha256 file.

The Node.js installer bin/gm-install.js also takes --mcp-only, which repairs an MCP registration without reinstalling anything, and --skills-only, which copies or links the skills and stops (no MCP registration, no runner).

2. Run a verb from a shell

A verb is a named gm command, such as codesearch. A verb does not need an agent host. To run a gm command from a terminal inside a checkout, use ./bin/gm, for example:

./bin/gm codesearch literal BUNDLE_VERSION --path gm-mcp/src

The command exits 0 and prints a data: block. Its exhaustive: true field reports that the scan is complete.

3. Connect the MCP server

The installed bundle is ~/.gm-tools/gm-mcp-server.mjs. Agent hosts launch it with Node.js from that local file. Registrations never launch the server through npx, because each connect re-resolves the package. Measured in README.md, a connect through an npx GitHub spec takes 8.2 s warm and 22.2 s cold.

If your agent host does not list the gm tool, repair the registration with the command that matches how you installed:

  • From a checkout of the repository, user registration: node bin/gm-install.js -g --mcp-only
  • From a checkout of the repository, project registration: node bin/gm-install.js --mcp-only
  • After the skills and MCP bundle install (the install argument in section 1): claude mcp remove gm 2>/dev/null; claude mcp add gm -- node ~/.gm-tools/gm-mcp-server.mjs
  • Any directory, user registration: claude mcp add gm -s user -- node ~/.gm-tools/gm-mcp-server.mjs (the bundle path above).

Restart the agent host after a registration change.

The transport is stdio only: a pipe that the agent host owns, with no listening port. gm opens no port on its own, so nothing collides with other services on the machine. A stdio connection does not recover after it drops; run /mcp and reconnect gm after a deploy. Transport details are in the Transport section of gm-mcp/README.md.

4. Check the runner and start the spool

On macOS or Linux, print the installed runner's build information:

~/.gm-tools/agentplug-runner --build-info

In Windows PowerShell:

& "$env:USERPROFILE\.gm-tools\agentplug-runner.exe" --build-info

The output is JSON with the fields version, commit, build_ts and release_build.

The spool is the .gm/exec-spool directory in your project, where gm requests and responses are exchanged. Run the runner's spool command from the project directory to serve it. The spool host writes its status to .gm/exec-spool/.status.json. Start it with:

~/.gm-tools/agentplug-runner spool

5. Source layout and submodules

The root .gitmodules file lists 11 submodules. To work on gm, clone the repository with all 11 submodules:

git clone --recurse-submodules https://github.com/AnEntrypoint/gm.git

For an existing checkout:

git submodule update --init --recursive
SourceResponsibility
skills/gm/SKILL.mdAgent workflow and tool routing.
gm-config/Default prose, gate text, messages and the workflow graph (fsm/graph.json).
rs-plugkit/The gm WebAssembly (WASM) guest: orchestration, memory and code search.
agentplug/The native agentplug-runner host.
gm-mcp/The MCP wrapper around spool request and response handling.
agentplug-bert/, agentplug-libsql/, agentplug-treesitter/Shared embedding, database and syntax plugins.
rs-codeinsight/Code structure analysis with tree-sitter (README.md).
rs-search/A dependency-free Rust library for rank fusion (Reciprocal Rank Fusion, which ranks candidate id lists) and tokenizing, used by the rs-plugkit WASM host (README.md).
agentplug-crux/Finds the rarest shapes in a large, low-signal-density corpus. A shape is one group of exact repeats, merged into one entry. Give it a directory and it reports the shapes that are rarest relative to the rest of the corpus.

Release status is on the gm releases page, which lists each published release (a release that is not a draft).
