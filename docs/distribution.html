Install gm and check
that it works

AnEntrypoint
Summary
gm is a state machine for coding agents. A gate decides when work is done, not the coding agent. This page is for developers who run Claude Code, Cursor, Codex or Gemini. The installers place the gm skills, the native agentplug-runner host and a local Model Context Protocol (MCP) server bundle. After install, the gm skill sends each request to the local runner through the project spool, .gm/exec-spool/, which holds in/ requests and out/ replies.

Next step: run the install command for your system in section 1, then check the runner in section 4.

1. Install

Pick the command for your system. Each one installs the parts it names:

  • Node.js, all parts: npx github:AnEntrypoint/gm -g installs the skills, registers the MCP server in each detected agent host (the app that runs your coding agent) and installs the runner. Drop -g to install into the current project only.
  • macOS or Linux, runner only: curl -fsSL https://raw.githubusercontent.com/AnEntrypoint/gm/main/install.sh | sh
  • macOS or Linux, skills and MCP bundle only: curl -fsSL https://raw.githubusercontent.com/AnEntrypoint/gm/main/install.sh | sh -s -- install
  • Windows PowerShell, runner only: irm https://raw.githubusercontent.com/AnEntrypoint/gm/main/install.ps1 | iex
  • Windows, skills and MCP bundle only: from a checkout, run install.ps1 with the argument install.

The Node.js installer bin/gm-install.js also takes --mcp-only, which repairs an MCP registration without reinstalling anything, and --skills-only, which materialises the skills and stops (no MCP registration, no runner).

2. Run a verb from a shell

A verb is a named gm command, such as codesearch. A verb does not need an agent host. In a checkout, ./bin/gm forwards to the same dispatch that the gm MCP tool runs, so a plain shell reaches the project spool with no MCP client in the loop.

./bin/gm codesearch literal BUNDLE_VERSION --path gm-mcp/src

3. Connect the MCP server

The installed bundle is ~/.gm-tools/gm-mcp-server.mjs. Agent hosts launch it with Node.js from that local file. An agent host is the app that runs your coding agent, such as Claude Code, Cursor, Codex or Gemini. A registration never launches the server from an npx GitHub spec. The MCP launch paragraph in README.md gives the reason.

If your agent host does not list the gm tool, repair the registration with the command that matches how you installed:

  • From a checkout of the repository, user registration: node bin/gm-install.js -g --mcp-only
  • From a checkout of the repository, project registration: node bin/gm-install.js --mcp-only
  • After the curl or irm install: claude mcp remove gm 2>/dev/null; claude mcp add gm -- node ~/.gm-tools/gm-mcp-server.mjs
  • From any directory, user registration: npx github:AnEntrypoint/gm -g --mcp-only runs the installer, which registers the node bundle path above.

Restart the agent host after a registration change.

The server also serves stateless streamable HTTP on the local machine, at http://127.0.0.1:8787/mcp. In Claude Code, register that transport with:

claude mcp remove gm -s user && claude mcp add --transport http gm http://127.0.0.1:8787/mcp -s user

Start the shared HTTP server, or confirm that one is listening, with node ~/.gm-tools/gm-mcp-server.mjs ensure-http. It starts the server when no listener exists. http-supervise supervises the server. The Transport section of gm-mcp/README.md owns the transport details.

A reply longer than max_chars characters (24,000 by default) is cut. The full reply is written to a spill file under .gm/exec-spool/out/, and gm_result reads that file.

4. Check the installed runner

On macOS or Linux, print the runner's build identity:

~/.gm-tools/agentplug-runner --build-info

In Windows PowerShell:

& "$env:USERPROFILE\.gm-tools\agentplug-runner.exe" --build-info

The output names the compiled commit and whether the build is a release build, in its commit and release_build fields.

The installers verify the skill archive and the runner against their .sha256 files. The gm-mcp server bundle is downloaded without a checksum.

The runner serves the project spool. Its status file is .gm/exec-spool/.status.json. The status file being recent does not prove that the runner process is running. Start the spool host with:

~/.gm-tools/agentplug-runner spool

5. Repositories

The root .gitmodules file lists 11 submodules. Clone them when you develop one of these dependencies:

git clone --recurse-submodules https://github.com/AnEntrypoint/gm.git

For an existing checkout:

git submodule update --init --recursive

6. Releases

The skill-release.yml workflow runs on a push to main that changes skills/**. It bumps the version in package.json, packages the skills into gm-skill-<version>.tar.gz, and publishes the archive with its SHA-256 file to a tagged GitHub Release.

The runner publishes from agentplug to the AnEntrypoint/agentplug-bin releases. A commit or a push does not prove that a release exists. Check the skill-release workflow runs at skill-release.yml and the assets on the gm releases page. A skill release is published when its gm-skill-<version>.tar.gz and its .sha256 file are both listed. The runner's assets are on the agentplug-bin releases page.

A change to the MCP wrapper requires rebuilding its committed bundle. A change to a dependency requires updating its pin in the root submodule.
