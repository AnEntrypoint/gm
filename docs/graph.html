The hop graph is the map a hop follows. A principle is one discipline from a named book or author. A hop applies one principle to one part of the code, then follows an edge to the next principle. Gates guard the edges they sit on, and tensions stay open until they are resolved. There are no phases: every node is independent, and the walk is a graph walk with many paths. This file is separate from the state machine that enforces the walk, gm-config/fsm/graph.json, which has its own states and gates.

Every node below is its own anchor, listed flat and in full: 146 nodes, none of them behind a bucket. Each one names every node it reaches and every node that reaches it, in both directions, so a walk can start anywhere and move node to node. The concern index above the list is provenance, not a gate: it says where each book came from and points at the same anchors.
